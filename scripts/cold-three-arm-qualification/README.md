# Cold BIOS three-arm semantic qualification — source preparation

This manual workflow prepares exactly one fresh plain-JS worker, native one-Q
worker and native batched worker, in that order. It performs no build, mixed
oracle rerun, warmup pairs or measured performance gate. The original
source-owned contract passed root source review. Its first hosted
qualification failed after plain JS completed: native one-Q initialized but
stopped before any resume on an inspect-schema assertion, and native batched
never started. This derivative contract refuses before setup until the corrected
native worker has a reviewed source freeze and binding. The workflow remains
disabled by default; another execution requires a separate root grant. Its pure
fixtures never execute a worker.

The first attempt used plain-JS 0f1ec8cc (49 source inputs, five pure
controls) and native 8ed0366a (55 inputs, eight pure controls). The old native
arm has not passed semantic qualification. Their complete
current/Git maps and exact raw source-control/independent-review records are
prerequisites before execution. These source controls do not qualify any guest.
Separate published Git checkouts retain the exact worker revisions, compiled
7632e6a (125 inputs) and diagnostic driver 11c0bdc (54 inputs). No frozen worker
or compiled C source is edited by this preparation.

The parent downloads and authenticates the original compiled artifact 11269563080
and successful eighth diagnostic artifact 11272405254. It reuses the existing
restore-only helper at the original qualified absolute paths and its original
provenance records. The eighth capture and independent audit are pinned byte
for byte; target N and Q are separately bound to their measured 316,562 values.
Each worker accepts its source-owned capture binding, not a caller-supplied one.

Each fresh worker has CPU 60 seconds, wall 120 seconds, Node 22.23.3, heap 128 MiB,
file 16 MiB, core zero, nice increment 10 and blank six hook variables. The parent
retains wait4 rusage, wall/timeout/raw exit/stdout/stderr, host context and complete
source/artifact/input authentication before and after each child. A first failure
stops all remaining arms. Final authentication failure forces FAIL and nonzero.

A narrow derivative of the existing paired policy verifies independent terminal native N/Q,
all 166 native CPU words, required counters, complete settled board and raw RAM
hash, source/build identity and the complete ordered actual PIO tape. Plain JS
checks its raw pre-settle E16 CPU plus strict final CPU/board/RAM/PIO. The existing
workers keep their actual real-device/deadline/line phases and timed loop intact.
Intermediate native words are mandatory ABI materializations but are discarded
by these workers; no per-instruction trace or per-element RAM parity is claimed.
The original diagnostic retained final RAM hashes, not complete backing bytes.

Execution-phase CPU/wall self-reports and whole-child wait4 evidence are retained
separately for investigation only. Cgroup host counters are aggregate and are
not attributable to one child. These three children cannot establish a paired
speed improvement, physical 386 RTx, broader AT boot, Windows/Doom 10×, or default
adoption. A successful raw qualification remains subject to independent audit;
the parent neither requires nor fabricates an armQualificationAudit to run itself.

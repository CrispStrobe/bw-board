# Passive ordinary-RAM linear reader model

This separate **source-only, unconnected** slice prepares the [AT code binding model](../i80386-cwsdpmi-at-owned/README.md) for a future actual guest adapter. The reader copies a bounded linear byte span directly from the AT machine's ordinary `Uint8Array` backing. It does not call the CPU's `_translate` or `_readLinear`, or the board's `_read386`, `_read` or device hooks: those can change paging A/D bits, translation-cache state, VGA latches or device state. Its input `sourcePaused: true` is a caller assertion, **not** an authenticated CPU pause lease. Integration must prove a synchronous owner-thread cut before using this reader to establish loaded-code identity.

The first profile is the compatible 80386 AT with a 16 MiB backing/address span but exactly 4 MiB of ordinary installed RAM: `00000h–9FFFFh` and `100000h–45FFFFh`. The base AT config also declares a separate `B8000h–BFFFFh` display-RAM region; the FreeDOS VGA variant replaces it with a VGA aperture. Both are excluded. The configured regions must match one of those two exact variants. The VGA variant additionally requires the actual `VGAMemory` class instance wired to `machine.chips.vga1`; the base variant requires no VGA memory object. Every page-table entry and final data page must fall in the two ordinary RAM windows and have board `_page` kind 1, meaning a whole ordinary-RAM page. ROM, VGA/MMIO, unmapped backing, synthetic MP/APIC and disabled A20 cases are refused. A20 must be configured and enabled. The model requires protected 32-bit code, no VM86/retained-real-CS state, and CR4=0; a PDE with the large-page bit is refused. With CR0.PG set, it walks 4 KiB PDE/PTE pages from CR3 using raw RAM bytes, enforces CPL3 user read permission at both levels, and copies across linear page boundaries without setting A/D or CR2. Read-only pages are permitted for reading; CR0.WP affects writes and is not used here. Without paging, the linear address is checked as a physical ordinary-RAM address. The helper is synchronous, rejects reentry and latches a failed model session.

Run `node scripts/i80386-cwsdpmi-at-loaded/passive-ram-control.mjs`. The bounded fake-machine controls cover page crossing, code bytes, no CPU/RAM/page-classifier/board mutation, user and supervisor permission behavior, absent and large-page entries, ROM/VGA/backing-only refusal, A20 and unsupported-profile refusal, arithmetic overflow and swallowed reentry. They do not execute FreeDOS, compile a client, compare actual loaded text, or observe `INT 2Fh`/`INT 31h` delivery and IRET. No AT or performance result follows. A future affected guest gate must bind the actual loader mapping and source pause authority and independently compare the fresh executable's linked bytes with observed guest RAM.

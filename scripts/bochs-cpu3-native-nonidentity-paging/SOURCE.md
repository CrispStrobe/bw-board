# Private nonidentity 4 KiB paging source proposal

This new finite private JS oracle enables paging from the identity-mapped low ROM, after the reset far jump has installed CS base F0000. CR3 selects directory 1000 and table 2000. GDT page 0 and the ROM page F0000 remain identity mapped; linear code 7000 maps to physical A000 and linear data 9000 maps to physical B000. Original physical aliases 7000 and 9000 contain deliberate poison and remain unchanged. The transition never executes from those aliases.

The program installs accessed code/data descriptors, loads the GDT and CR3, sets PE, loads DS, then sets PG in the identity ROM and far-jumps to code16 selector 18. A separate NOP proves the first nonidentity code fetch; MOV BX,[9000] proves data read; MOV word [9002],5678 proves dirty/write effects; MOV DX,[9002] observes the value. It stops before HLT. Eleven named cuts distinguish these phases. Strict386, CR4=0, 4 KiB pages, supervisor present/writable entries, IF=0, stable A20, no faults/IRQ/PIO/REP/disk and a 512-instruction maximum are fixed, with no caller configuration.

The ordinary CPU remains unchanged. The AT constructor's unused compatibility CPU is replaced before its first instruction by a real strict386 instance on the same private board. That instance uses the earlier exact-source MOV CR0 derivative and explicit Bochs reset model; no post-step state normalization is used. JS paging source 399–472 sets PDE/PTE accessed and leaf dirty bits; genuine compiled Bochs paging.cc SHA e72fcf4f21a32b5618eeeb2e783f4faef8feea4f2d1f0dc8b3cb6515858e4f5d lines 1259–1284 independently ground those A/D semantics. Six expected JS page-bit transitions are guarded by exact owner, address, old/new values and byte order. Their JS callback order is not yet a native callback-order claim. Fetch access must leave the code PTE clean, the first data read sets only A, and the later write sets D. No PSE or CR4 extension is admitted.

All seven complete physical pages are copied and checked after every instruction. Actual physical fetches and ordered physical bus reads, owned boot/data stores and page-bit updates are retained. Snapshots are detached, stage uses actual chip debt/IRQ state, and settlement hashes whole raw physical RAM. A clean current/Git source inventory includes the dynamic CPU-source seed and static import closure. Source controls and the bounded fixed JS execution remain pending at this proposal; no new native policy, materializer, build, addon admission, paging guest, broader OS or performance claim exists. The qualified stack profile and addon4076 remain unchanged and are inadmissible for a future paging guest.

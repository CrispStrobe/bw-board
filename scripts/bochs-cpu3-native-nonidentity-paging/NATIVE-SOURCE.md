# Native nonidentity paging policy proposal

This separate source derivative keeps the qualified stack runtime/provider immutable. It requires a new generated runtime, private provider, ROM, profile, build context and addon identity; neither the stack addon 4076 nor another held addon admits this profile. Preparation, compilation, native CPU execution and differential qualification have not run.

The fixed JS program remains unchanged: linear 7000 fetches physical A000, linear 9000 reads/writes physical B000, and original physical 7000/9000 retain poison. The GDT, directory, table, ROM and two aliases remain independently observable. The C fetch predicate now obtains the physical address from the existing `pAddrFetchPage` and biased EIP (genuine prepared cpu.cc lines 633–685), then requires that address to equal the profile's owned translation. It does not make a second paging walk, infer identity addressing, or use a stale instruction owner to select a physical page. Both the copied execute page and every fetched byte retain the held generation/hash/cache/publication checks.

The non-PAE walk policy admits only directory address 1000 and PTE addresses 2000, 201C, 2024 and 23C0, always complete four-byte entries with original address, permission and reserved bits intact. Walk kinds 1/2 are reads; kinds 3/4 are PDE/PTE A/D writes. PDE and code/GDT/ROM leaves admit only A; the data leaf admits read A followed by write D. No PDE dirty bit, code dirty bit, new entry, page size extension, fault delivery, IRQ, CR4 extension, data execute page, stack access or unowned write is admitted. Ordinary operand reads are separately owned by LGDT, MOV DS, far jump and the two mapped data loads. The sixteen boot dword stores and single mapped word store retain exact owner/address/width/value and per-page generation checks.

Walker ownership is distinct from ordinary attempted-instruction ownership. Prefetch reads/writes use live F000:farJump or 18:7000; their previous `bw_attempt` may be stale. Descriptor walks use the advanced live ROM PC with the recorded far-jump attempt. Data walks require both the corresponding recorded RAM attempt and advanced live PC (7001→7005, 7005→700B, 700B→700F). Unknown phase/address/kind/length combinations refuse before effects. The original Bochs legacy walker and `update_access_dirty` (paging.cc SHA e72fcf4f21a32b5618eeeb2e783f4faef8feea4f2d1f0dc8b3cb6515858e4f5d, lines 1157–1174 and 1259–1284) ground the full-dword effects; JS callback ordering and JS page-generation counts are not imposed on the native backend.

The provider retains actual ordered native reads/writes with their callback extents, independent generations and seven copied physical pages. The future differential driver must compare represented CPU fields, real full boards and all seven pages at matching instruction cuts while retaining all 166 native words and separately explaining any backend-only prefetch/walk boundaries. Native-only hidden fields are separate source expectations, not fabricated JS counterparts. Existing raw reset/MOV CR0 model semantics remain explicit; there is no post-step normalization, flag mask, whole-RAM normalization or physical timing claim.

The source predicates and exact hash/count/inverse transformations are ready for review. Proposed controls cover mutated held sources, wrong live/attempt walk owners, unknown addresses/kinds/lengths/permission bits, early/duplicate stores, poisoned execute aliases, actual private provider callbacks without CPU execution, and the actual generated C policy functions in a tiny nonguest fixture. No control result is claimed yet.

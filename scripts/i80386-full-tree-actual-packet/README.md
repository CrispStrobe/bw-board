# Nine-role packet consistency writer

This portable, source-only module writes a bounded text packet. It does not run the acquisition controller, coordinator, compiler, guest, or any network request. It supplies neither authenticated context nor complete profile-source admission. The existing runner remains unchanged and unarmed.

`Packet(destination).write(members)` accepts an exact built-in dictionary containing immutable byte values. Admission checks precede filesystem access. A private snapshot of those bytes protects later writes from caller-map mutation at an OS callback boundary. Each fixed filename is attempted once with exclusive, no-follow creation in a retained ordinary directory route. The destination must initially be empty; a bounded final directory census must match the emitted role set. Partial files remain on refusal. Nothing is deleted or retried.

The fixed role caps are 64 KiB each for source-before/source-after JSON; 4 KiB event JSON; 192 KiB report JSON; 8 KiB each for control/run stdout/stderr; 1 KiB status. The decoded packet cap is 512 KiB. Reads, writes, and readback use at most 64 KiB per call. Per-file observations check regular type, link count one, initial empty extent, written bytes, final extent and named/opened identity. These finite checks do not certify an uninterrupted namespace or filesystem lease. Close attempts consume their ownership slot first; a refused close is uncertain and is never retried blindly.

The event schema `bw.full-tree-actual-event.v1` has exactly schema/event/action/repository/headRepository/pr/head/base/run/attempt/workflow/job/label/authenticatedContextQualified. It describes an own-repository pull_request labeled event, positive primitive PR/run IDs, attempt one and hexadecimal head/base. Proposed workflow/job/label names are constants in the module, not existing official identities. `authenticatedContextQualified` must remain false. Public-shaped values and serializer agreement cannot authenticate their origin.

Status is exactly two ASCII LF lines: `phase=<stage>` and `exit=<decimal>`. Stages are entry, event, source-before, controls, execution, source-after and complete. Complete requires exit zero and all nine roles; every other stage requires a nonzero exit up to 255. The exact required/allowed partial role sets are the module's REQUIRED/ALLOWED constants. Terminal status is required for an admitted assembly; source/report bytes that were never produced remain absent. JSON null is not a report placeholder. The private filesystem failure status can separately describe an interrupted assembly that never finished writing its terminal file.

Complete packet assembly requires a report with complete=true and empty control/run stderr. A negative outer stage may retain an unchanged complete historical report, because a later outer source/status/artifact step can fail. It does not become packet success. Raw source positions join the corresponding report fields. The report's closed top-level schema and false authority flags are checked here; complete nested source/report semantics remain the independent reader's duty. Inherited fourteen-row source snapshots do not admit the runner, packet writer, future executor/admission/workflow, or original reader.

Logs use a conservative ASCII fact grammar, terminal LF and at most 240 characters per line. CR, TAB, VT, FF, other controls, URLs and path separators are refused. This is not a redaction engine or a raw stderr/trap preservation mechanism. Future raw failures and authentic command transcripts need separate retained provenance; they must not be normalized away to fit this envelope. No command exists here from which controlTranscriptQualified could follow.

All original-packet, context, profile-source, filesystem, source-ownership, compiler, guest and performance qualifications remain false, including after complete assembly. Byte readback is finite content consistency, not durability. Partial artifacts remain; handle cleanup is not filesystem deletion or process security.

Twenty-five manufactured controls exercise closed JSON/events/status, caps/partial roles, primitive admission, LF/control-character refusal, nine-role serialization without semantic authority, negative historical report preservation, exclusive destination/foreign-file retention, caller-map mutation, reentrant returned-FD cleanup, primary write error with close refusal, byte mutation readback, final foreign entry, and once consumption. Only manufactured temporary files are used. An initial log-regex test error was corrected; the final suite passes. No actual inputs, product helpers or transport are exercised by these controls.

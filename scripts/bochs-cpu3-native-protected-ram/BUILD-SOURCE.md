This separate proposal adapts the existing RAM preparer and static build helper through exact parent hashes, counted replacements and byte-exact inverse checks. The original cold and RAM materializers create their historical intermediate records; the protected finalizer retains them explicitly and owns the new runtime, ROM and provider roles. It does not relabel the old RAM addon as a protected build.

The new manual workflow defaults disabled, checks out its exact GitHub SHA, fixes Node 22.23.3 and pristine Bochs 0e45b736, and performs preparation/compilation/static admission only after a separate root-reviewed dispatch. Raw streams, stage exits, source/generated/config maps, full prepared-source inventory/archive and build context are retained even on failure. Importing the preparer or build helper only constructs checked definitions.

Six source controls cover pure manifest/configuration admission, preparer and builder inverse/refusal, build-context denials, disabled workflow scope and complete current/Git/generated maps in an owned clean checkout. The test wrapper removes Node's internal NODE_TEST_CONTEXT only for the standalone nested suite and requires its genuine six passes, zero failures/skips. These controls create diagnostic metadata/configuration files but never prepare Bochs, configure, compile an addon, load it or execute a CPU. Actual protected build and a new differential driver remain pending.

The native protected RAM profile derives the qualified real-mode RAM runtime and the qualified cold provider through exact source hashes, counted seams and byte-exact inverse checks. It preserves ABI4, original clock leases, pending-write ownership, generation tables, current-code and admitted-unexecuted-code write refusals, and native PAGE copying.

The fixed program owns four stores: two four-byte descriptor stores at 0618/061C and two two-byte code stores at 7000/7002. C additionally requires their exact ROM CS:EIP and prior page generation. The host provider requires their complete ordered sequence before RAM execute admission. The entire 4096-byte code page must equal the source-owned bytes at generation 2. Reads admit only the LGDT operand at F0180–F0185 from F000:0124 and the GDT descriptor at 0618–061F from F000:0133, with descriptor bytes checked after the actual host read. Other memory data accesses, PIO, IRQ delivery, faults, HLT and paging are denied.

Instruction admission allows the reset jump, the fixed real-mode ROM setup, its PE-enabled far jump, and selector 18/base 0/code16 MOV AX,1234 at 7000. The ordinary checkpoint precedes HLT at 7003. Caps of 512 N/Q are maxima; no native instruction total is asserted. The earlier private JS profile's 13 instructions are separate source/model evidence, with its explicit Bochs CPU3 MOV CR0 derivative; ordinary JS and old compiled DSOs remain unchanged.

Build admission uses distinct protected manifest, generated ROM/provider roles, receipt and context schemas, preserving complete RAM/cold/H4 derivation provenance. An old RAM or cold receipt cannot establish a protected build. The source plan authenticates all current/Git inputs and generated hashes; it does not materialize sources, configure, compile, load an addon or execute a CPU. A new protected materializer/build and a separately reviewed native differential run remain pending. Source controls compare actual generated C predicate bodies and original host-provider callbacks, not a new native core.

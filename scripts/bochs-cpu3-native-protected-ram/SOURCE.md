# Protected code16 RAM entry proposal

This separate source-only profile reuses the combined-paging-RAM layout's GDT at `0x600` and selector `0x18` for base-zero, 16-bit code. The fixed ROM creates an already-accessed `0x9b` code descriptor and a one-page RAM program, executes LGDT and MOV CR0 to enable PE, then far-jumps to `18:7000`. MOV AX,1234 is the sole protected-mode RAM instruction. The ordinary checkpoint is `18:7003`, before HLT. Paging, interrupts, faults, disk and PIO are excluded. Caps are maxima, not measured instruction totals.

The no-argument private JS oracle installs the prior explicit Bochs reset profile before its first instruction. Ordinary JS MOV CR0 masks `0x8000001f`, whereas the actual compiled CPU3 source forces `0x7ffffff0` (first RAM build run `37136096190`, `bochs/cpu/crregs.cc` SHA `f39cb6b7b1f7b030690104dcd31e839651a6d343784d8a072e5b337d17fcd374`, lines 1082–1084). A separate exact-hash, single-replacement, byte-exact inverse derivative changes that assignment in the private CPU prototype. Ordinary repository CPU bytes remain unchanged. This is an emulator model profile, not a hardware correction or post-step snapshot normalization.

Named cuts independently check GDTR and the entire GDT page, raw CR0.PE, every represented far-jump code-cache field and RAM AX value. Raw GDT bytes separately establish descriptor type/S/accessed/DPL/G/DB/AVL; no unrepresented JS hidden-cache fields are invented. The oracle provides copied 4096-byte GDT/code pages and full board state at paused boundaries. Every actual byte write must belong to one of the four exact initialization stores, and complete page bytes are checked after each instruction. Source controls cover encoding, refusal policy, source derivative, manufactured milestone states and a tiny ordinary-JS execution to the checkpoint. Those controls are pending execution at this draft; no native guest has run.

The previous real-mode RAM profile, build, driver and DSO remain frozen. This proposal admits no addon. Extending the native C fetch/data/page policy, adding independent source/build admission and the reviewed one-Q differential driver remain separate work before a fresh protected-mode build or execution. Future native comparison must retain all 166 raw words and compare represented CPU fields exactly, with dynamic CR0 phase ownership; native-only hidden fields must not be labelled JS counterparts. No protected-mode success, paging, OS or performance claim is made here.

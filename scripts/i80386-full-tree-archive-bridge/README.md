# Manufactured TAR-to-writer bridge

This candidate joins a synthetic authenticated TAR.BZ2 parser to the hash-bound sibling full-tree writer. It has not parsed actual archive inputs or provisioned the default 1196-file tree. No actual archive acquisition, compiler, guest, or application integration is included.

`Bridge(parent).provision(toolchain, djcrx, djdev, djlsr, notices)` accepts four exact builtin immutable byte values and a separately untrusted exact builtin notice-chunk dictionary. One attempt is consumed before admission. All four fixed extents and SHA256 pins must match before decompressor or writer construction. The three ZIP inputs are authenticated opaque bytes in this slice: their bodies, source-origin joins, contents, and notice origins are unvalidated. No caller writer, FD, expected pin, extractor, or callback is accepted. The five pinned notices are a selected metadata-derived subset outside those four archive inputs; matching their hashes does not establish source ownership, complete notice coverage, or legal clearance.

Only the toolchain TAR.BZ2 is parsed. Paths, types, extents, and file hashes must match the exact frozen reported manifest: 1196 ordinary files, 78 directories, and 13 aliases to 11 prior ordinary targets. Unknown, missing, duplicate, symlink, unsupported type, file-ancestor conflict, wrong alias target, and copied-alias policies refuse. The strict GNU L subset mirrors the earlier source contract: GNU sentinel, empty link/prefix, bounded ASCII name, exactly one final NUL, metadata payload at most 241 bytes, zero padding, one pending name for the immediately following ordinary file/directory/fixed hardlink, and short-header placeholder equal to the first 100 name characters. This placeholder restriction is a finite subset, not general GNU compatibility. K/PAX remain unsupported. Ordinary TAR padding is also required to be zero in this bridge, a stricter explicit subset. POSIX/GNU magic and octal fields/checksum are checked; this is not a complete physical TAR-format validator.

BZ2 output is incremental, capped per decode at 64KiB and at 3GiB total decoded bytes including headers, metadata, padding, and tail. Truncation, concatenation, unused compressed data, nonzero decoded tail, and absent end blocks refuse. The decoded buffer stays below 128KiB. Header count includes GNU metadata and is capped at 30,000. Known ordinary extents are reserved before reading: 34,200,152 bytes per file and 258,686,704 bytes aggregate. At most the manifest-derived sum of ceil(file extent/64KiB) cache chunks is reserved before body reads, with no unbounded body inventory. All ordinary chunks are cached until whole archive closure so malformed archives do not create a root. These are finite content/allocation bounds, not sufficient RAM/disk/time budgets: inputs, chunks, Python objects, decompressor and filesystem overhead coexist. No old selected-nine cap changes.

The 120-second monotonic deadline is cooperative at authentication/parser chunks and delegation boundaries, not a hard process deadline or per-writer-syscall deadline. After full parse closure, only the internally created hash-bound writer receives source-built ordinary chunks and the separately admitted notices. It performs exclusive creation, physical alias policy, final canonical/notice readback and close accounting. Bridge status/provision/close reentry during writer work latches bridge refusal and immediately poisons the internally active writer through its known private `_fail` method; swallowed callback reentry stops later ordinary writes. Original exceptions retain identity across cleanup. Partial filesystem artifacts are retained; close refusal is descriptor uncertainty, not successful filesystem cleanup. Parent creator trust and first-post-mkdir identity limitations remain inherited.

Status exposes copied counts/fixed reasons and source-issued primitive writer status, no paths, FDs, tokens, bodies, or adopted caller receipts. All opaque ZIP source-join, notice source/complete coverage, raw actual archive compatibility, filesystem lease, source ownership, full toolchain, compiler, guest, and performance flags remain false even when synthetic observations complete.

The controls patch synthetic manifests, pins and notice fixtures. They use small builtin synthetic TAR/BZ2 bytes and manufactured filesystem calls only. The preserved first fixture failed because the test builder accidentally emitted 510-byte POSIX headers; this is not an actual archive failure. Corrected final controls passed 25 methods, including delegated reentry, pre-auth refusal, GNU boundary/invalid metadata, alias ordering, budgets, cross-chunk truncation, and original write error with uncertain close.

Revision 2 gates parser entry before decoder construction or inventory/count work: entered once, busy internal parsing phase, four authenticated inputs, open bridge and unconsumed parser entry are required. New, closed, completed or wrong-phase direct calls refuse without decoder/counter work. Nested parser entry latches bridge reentry; parser misuse during delegated filesystem writing also poisons the active writer. This source-owned lifecycle gate is not a security claim against arbitrary Python reflection or field mutation. Earlier source preparation exposed direct parser entry before authentication; the guard now refuses it before decoder construction. This description does not bundle earlier candidate files.

Run the source controls from the repository root:

```sh
python3 -I -B scripts/i80386-full-tree-archive-bridge/controls.py
```

The accompanying PR workflow runs only these 25 manufactured controls. It does not acquire archives or execute a tool, compiler, CPU or guest. The sibling [writer](../i80386-full-tree-provisioner/README.md) supplies the finite filesystem behavior; this bridge adds no live source or runtime authority.

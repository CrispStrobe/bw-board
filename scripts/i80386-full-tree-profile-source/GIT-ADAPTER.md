# Fixed-operation Git adapter draft

This portable source-only unit is unconnected to the frozen source gate. Its external descriptor seal remains None. It performs no network operation, acquisition, source import, compiler/tool/CPU/guest execution, or operational launch. Real Git controls use only tiny manufactured temporary repositories. No product checkout is queried by the controls.

`Adapter(checkout, descriptor_raw, table_raw).read(operation, relative=None)` supports only head, origin, detached, clean and blob. Descriptor/table bytes must match an external reviewed seal and fixed head/own-origin/explicit path/extents/hash/blob record. This adapter checks the transport-oriented shape and byte bindings; the separate full-profile gate/reader must enforce inherited membership, kind/workflow/transitive graph closure and official context. It supplies no standalone complete-profile qualification. The HEAD/descriptor seal must be reviewed outside the source commit to avoid embedding a cyclic self seal.

The internal command surface requires an active source-created fixed operation and matches exact operation-specific argv, cap and accepted exit codes before spawning. There is no arbitrary caller command, environment, Git binary, transport, callback or FD override. `/usr/bin/git` is invoked with argv and no shell. Global/system Git config and parent environment injection are disabled. No replacement objects, optional locks, lazy fetch, pager, hooks, fsmonitor, textconv, external diff or allowed transport protocols are supplied. Origin config is read locally without includes. This is a controlled Git plumbing subset, not general hostile-process/configuration security or executable provenance qualification.

A no-follow OS-root-anchored directory route retains the checkout, ordinary `.git`, objects and info directory identities. Linked-worktree `.git` files, external alternates, nonempty shallow metadata and symlink routes are unsupported. Before/after process and source-file operations recheck retained directory identities. Admitted blob mode is strictly regular 100644; symlink and gitlink modes refuse. Git source data and live file hashes are checked against the explicit externally sealed map. No raw descriptor values, host paths, file descriptors or stderr are emitted in status.

The clean operation is deliberately `INDEX_AND_EXPLICIT_SOURCE_ROLES_ONLY`. It uses a fixed cached raw tree/index diff with no worktree conversion and hashes only admitted files/table. It does not call git status or worktree diff, execute attribute clean/smudge filters, traverse submodules, scan unrelated files, or establish global untracked/worktree cleanliness. A future supervisor must explicitly admit this narrower meaning before connecting it to the held gate's clean surface. The adapter itself does not change that gate.

Each context operation is bounded to four calls; each explicit blob path to two. At most 424 fixed Git commands can be issued. Pipes are read in chunks no larger than 64 KiB and the remaining cap plus one guard: context stdout is 41/128/256/4096 bytes, blob stdout its exact admitted extent up to 512 KiB, stderr at most 4 KiB. Each process has a five-second deadline and launches have a 120-second aggregate deadline. These are bounded subprocess controls, not a hard bound on OS directory/file operations or filesystem availability. A future hosted outer process/resource bound remains required.

Popen/selector setup is protected immediately. On refusal, cap or timeout, the owned process group is killed even if its leader has exited and a descendant might retain pipes. Selector, pipe and process cleanup are isolated so secondary failures cannot mask the original error or skip remaining cleanup. Directory FD close attempts are consumed before close; uncertainty is reported and not retried blindly. Final cleanup reentry poisons and refuses after attempting remaining owned handles. Git output refusal is sanitized to a fixed code; original Python exception object identity is retained for the caller without printing messages.

Twenty-three manufactured controls create and dispose their own tiny Git repositories. They cover all fixed operations, external unarmed refusal before Popen, unknown paths/commands, own-origin and detached checks, index/live changes, symlink routes/Git directory, hostile attribute filter marker remaining absent, consumed blob budgets, setup/selector dual-error preservation, returned-FD reentry, parent environment injection, external alternates refusal, exited-leader pipe timeout kill accounting, hash-constructor reentry, and final directory cleanup reentry. Process descendant behavior is a manufactured mocked transport cut; actual Git operations execute only in the temporary repositories. All controls pass. No actual input or product source execution occurred.

Operational source admission, complete transitive graph/context, source ownership, filesystem leases, compiler, guest and performance flags remain false. The Git executable/interpreter/OS trust, exact future repository checkout and official workflow/event/resource/original/once-launch gates remain independent requirements.

The blocked first candidate is preserved byte-for-byte in candidate-v1. V2 latches an original returned-FD registration error before its fallback close, consumes that close attempt once and counts close refusal without masking the original exception. Command route/cap/deadline setup is enclosed in the protected cleanup region, so refusal clears command_busy even before Popen. Targeted dual registration/cleanup-reentry and pre-Popen setup controls cover both cuts.

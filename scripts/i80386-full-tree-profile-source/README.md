# Complete-profile source-position gate draft

This portable source-only draft observes an explicit reviewed profile graph. It does not execute a product, import an admitted source role, contact a repository, or implement Git transport. EXTERNAL_DESCRIPTOR_SHA256 is None and the internal fixed-operation `_git` interface refuses every production call. There is no caller delegate, FD, callback, pin override or importer API. All operational/source/lease/compiler/guest/performance qualifications remain false.

`Gate(checkout, descriptor_raw, table_raw).observe(position)` accepts only before then after, once each. The constructor validates primitive bounded arguments without filesystem access. A reviewed supervisor outside the commit must bind the exact descriptor-byte SHA. Embedding that SHA in the same Git source tree while the descriptor includes that tree HEAD creates a selfcycle; publishing another source version does not solve it. The current prototype stays None and has no public caller override or arming API. A future external seal handoff must be independently reviewed and bound to the unchanged gate algorithm before operational admission. A table cannot self-certify its own bytes or HEAD. Descriptor bytes, table bytes and the admitted external digest are captured before hookable work; later object/global changes cannot substitute a different original table or stamp a new seal onto a snapshot.

The closed descriptor `bw.full-tree-profile-descriptor.v1` binds schema/status/head/repository/origin/workflow/branch/pr/tablePath/tableBytes/tableSha256/tableGitBlob. It is explicitly UNARMED_SOURCE_ONLY, own-repository, with a forty-digit lowercase hexadecimal head, positive primitive PR number, canonical branch up to 120 characters and an exact workflow path.

The closed role table `bw.full-tree-profile-role-table.v1` contains schema/inheritedRoleCount/roles. It admits 21 to 100 explicit relative paths with exact kind/bytes/SHA256/Git blob rows. Every one of the fourteen frozen inherited paths/extents/hashes/blob IDs is mandatory with inherited kind. Separate runner, packet, admission, admission-control, executor, executor-control and workflow kinds are required. The advertised workflow itself must be present with workflow kind. No wildcard/prefix selection, unknown kinds, dot components, symlink route, or ancestor file conflict is admitted. The tracked table path is observed separately against the external descriptor and must not appear in its own rows, avoiding circular self hashes. Kind names and an external seal alone do not prove transitive import/resource closure, dependency provenance or source ownership; that remains an independent review requirement.

The snapshot `bw.full-tree-profile-source.v1` is separately versioned from the old fourteen-row runner observations. It carries position/head/repository/roleCount/roles, separate table path/extent/hash/blob, admitted descriptorSha256 and eight false qualification flags. It never reinterprets an old inherited-only observation as complete-profile authority.

Bounds: descriptor input at most 8 KiB, table at most 64 KiB, explicit source role at most 512 KiB, snapshot at most 64 KiB, at most 30 path components/240 relative path characters, and fixed 64-slot FD accounting. File reads stream in at most 64 KiB chunks with a declared-extent plus one guard. Before/opened/named regular file identity/extent/timestamps/link-count checks and retained directory dev/inode checks bound each observation. These finite positions do not establish continuous identity, path ownership, namespace security, durability, or a filesystem lease. OS/root/mount and parent provenance remain external trust surfaces.

The unimplemented Git adapter has only fixed head/origin/detached/clean/blob operations. Manufactured controls privately mock it; no arbitrary caller operational delegate is accepted. The draft checks head/origin/detached/clean before and after each snapshot and compares exact Git blob bytes and source bytes to the sealed rows. A future bounded no-replacement Git implementation and official exact-head/profile/event/checkout admission require separate reviewed source, controls and launch gates before any actual input acquisition.

Every close attempt consumes its FD slot first. Refused closes are uncertain, not retried blindly, and reported separately. First original errors survive secondary close failures. Busy observer reentry poisons the operation; cleanup attempts remaining owned descriptors and then refuses even if the callback swallowed the reentry error. No shared checkout is reset, cleaned, stashed or modified.

Twenty-one manufactured controls use small synthetic source files, a private replacement fourteen-row fixture, mocked Git and a privately patched external descriptor seal. They cover before/after positions, default unarmed refusal before Git/opens, wrong seals/bytes, symlink leaves/ancestors, wrong Git objects, order/close/reentry, strict JSON primitives, inherited membership, workflow omission/miskind, both-order ancestor conflicts, hash constructor reentry, original read plus close error identity, metadata substitution cuts, returned-FD reentry close accounting and final head drift. They do not run real Git, product sources, tools, compiler, guest or network. No test failures occurred in this development checkpoint; early review findings were addressed before freezing.

Excluding the table from its own rows resolves the table-row hash cycle only. It does not resolve the descriptor HEAD/embedded-source-seal cycle. An external immutable review/supervisor record must handle the latter without interpreting caller assertions as approval.


The independent `reader.py` validates the separately versioned descriptor, role table and before/after snapshots without importing the producer. Its sixteen manufactured controls reject the old inherited-only observation schema, extra or missing inherited-kind paths, an omitted or misclassified advertised workflow, contradictory table Git blob IDs, ancestor conflicts, over-cap descriptors and false-flag/type laundering. `inherited-roles.json` and `inherited-git-blobs.json` retain only public source paths and source digests. They contain no archive, tool, notice or guest bodies.

Run `python3 -I -B scripts/i80386-full-tree-profile-source/controls.py` and `python3 -I -B scripts/i80386-full-tree-profile-source/reader-controls.py` from the repository root. The first suite uses manufactured temporary source files and mocked Git; the second uses manufactured JSON. Neither suite executes product sources or authenticates an original job. The reader's operational review/table seals remain unset. Git adapter integration, externally approved supervisor/head binding, actual resource/execution provenance and official original-artifact admission remain separate tasks.


The standalone `git-adapter.py` component supplies fixed Git plumbing operations for future integration. It remains unconnected to the gate, whose external seal and production Git stub are unchanged. Run `python3 -I -B scripts/i80386-full-tree-profile-source/git-adapter-controls.py` for its twenty-three controls on tiny owned temporary repositories. No product checkout, archive inputs or network are used by that suite. The adapter's clean result covers the index and explicitly declared files only; unrelated worktree or untracked cleanliness is not established. See [GIT-ADAPTER.md](GIT-ADAPTER.md) for process/output bounds, retained failure limits and remaining supervisor requirements.

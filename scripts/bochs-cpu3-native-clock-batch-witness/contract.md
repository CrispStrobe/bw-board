This source-only witness validates an ordered successful-work/native-tick model and authenticated capture files. It implements no native batching ABI, private actual facade, device admission or performance backend. Original H4 runner, facade, wrapper, native runtime and addon remain unchanged.

Existing bf12 host journal and canonical BWSD1 capture authenticate exact N/Q chronology. They have no resume entry/return rows; 8,322 clock runs are not legal batch spans. The audit must report missing observer/resume fences, even when chronology matches. Do not infer 439 resume cuts from budget arithmetic: due, faults, PIO, selected checkpoints, IRQ and HLT cut earlier, and the terminal HLT return can charge zero work.

The separate fenced H4 diagnostic runner requires full native trace and compact host journal. It reads the source-known facade's compactCount and ledger fields, without extra inspect calls or changes to dynamic callback lookup. Its additional bounded regular-file journal labels start, stage-irq, resume entry/return (including requested independent caps and native result/reason), existing checkpoint inspection, terminal settlement and close. The original H4 compiled binary/source revision remain separate from the new diagnostic driver source closure. Added synchronous writes make its timings diagnostic only. Fences are recorded after native return snapshots already exist; the future batch ABI must flush before those snapshots, not only before this diagnostic record.

## First future native batch contract (not implemented)

Use a distinct versioned opt-in ABI and internal factory-created actual facade with private machine/ledgers, captured original methods, exact owned free ROM/configuration and no caller hooks or external mutation/input during resume. A brand token or frozen packedScalar alone is insufficient; reject arbitrary board objects, Proxy/subclass overrides and accessor/method mutation before execution. Generic H4 dynamic method/getter behavior retains its existing path. Tests of the offline model do not establish this ownership contract.

N and Q are distinct. Successful ordinary or zero-count REP work charges one Q and six functional board clocks. Each successful REP element charges one Q, including final element once; failed element earns zero Q. Native fault ticks charge N without Q; partial REP can temporarily have Q with no outer N. HLT idle has neither new CPU Q nor N. Preserve exact ordered event tapes, not count-only totals.

At entry after board chip settlement, calculate ceil((chipDeadline-chipDebt)/6) successful units until the existing first-unit-at-or-past deadline cut. Refuse unsettled due debt. Clamp independent requested Q/N budgets and remaining totals before execution; protect six-times-Q addition from overflow. Keep absolute native deadlines separate; faults make device deadline conversion to N invalid. Stop at the same committed instruction/REP element before next work.

Flush pending ordered clock events before every memory read/write, PAGE admission, PIO, actual PIC ACK, board/native inspection, snapshot, fault/IRQ/HLT cut, return, stageIRQ, terminal settlement and close. Flush preceding successful debt before PIO; current PIO instruction Q is charged after its effect. Rearm horizon from post-PIO board state. Preserve all A20 epochs, pending mapping ordinary-boundary publication, RAM generation, code alias stamps, prefetch/TLB/CR3/A-D/fault-frame guards and zero native fallbacks. Do not batch memory effects or widen port/guest admission.

Exception delivery requires chronology: prior committed clocks precede fault-frame callbacks, then the longjmp native tick precedes fault-delivered and return. Store pending state outside skipped stack destructors. No fault Q or premature fault N. IRQ acknowledgement remains the actual eligible Bochs/PIC path; host INTR changes occur only between resumes.

Diagnostic batch tape must identify every N(count)/Q(kind)/due change and cumulative ledgers at original logical positions. An independent offline expansion must reproduce original host logical events and every canonical CPU row, RAM/PIT fractional/PIC state and PIO chronology. Separate logical notification counts from actual host crossings. Added batch records cannot mask or normalize away original clock/device records. The offline specification model requires explicit intermediate/final REP tick classification; the present native clock rows alone do not carry that classification. This is model input, not inferred actual admission. Current-profile logical N notifications are exactly count1. Pure model mutations must deny reordered/dropped tape, omitted final flush, fault Q, final REP double charge, cap overflow and every observable barrier. Actual source-bound built proof and an unprofiled predeclared CPU gate are later validation gates; no speed/10x/broader guest/broader game/native CLI/GUI/full AT claim follows here.

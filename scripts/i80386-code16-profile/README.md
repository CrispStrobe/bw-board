This separately named hosted diagnostic runs one fresh profiled Node child A then B through the unchanged authored 2.4-million-instruction ordinary code16 fixture. It does not rerun or extend the seven unprofiled pairs, satisfy the original benchmark gate, grant CPU adoption or measure physical RTx or operating-system compatibility.

Two helper bodies authenticate by fixed SHA before fresh loading; only their source admission and semantic validation are used, never paired main/evaluator. The three new diagnostic roles and Node executable join actual Git/live bytes before and after each child. All ESM resolver package metadata is included. No source follows a moving revision and no firmware, disk, private media, native backend or accelerator is used.

Node 20.20.2 uses a 512 MiB old-space limit and a requested 1,000-microsecond V8 CPU sampling interval. No child is retried or replaced, and a reaped process group is never signalled.

The dedicated workflow accepts only its own implementation-branch push, own repository/head and first attempt. Missing enforcement or uncertain source, capture, resource, reap or cleanup facts refuse.

Raw profiles, child stdout/stderr, usage, resources and sources are retained before reduction. V8 covers its recorded sampling interval and represented startup; whole OS-process startup coverage is not assumed. Both fresh processes include setup/source/hash work and are not JIT-warmed by earlier children.

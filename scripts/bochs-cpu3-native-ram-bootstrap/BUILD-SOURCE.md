# RAM bootstrap build source (not executed)

The separate materializer invokes the hash-pinned cold preparer, preserves its
original manifest and H4 provenance, then writes the RAM runtime, generated
64 KiB ROM and generated provider into fresh prepared roles. ABI 4 and its
copied-response NAPI remain unchanged. The manifest binds every generated
output and the complete inherited and RAM/build source inventory.

Build admission derives the existing FS/hash/Git verifier by exact source
hashes, replacement counts and inverse proof. RAM receipt/context schemas and
profile are distinct. The old cold-BIOS addon/receipt cannot be admitted. The
configuration uses only the generated ROM role under the authenticated
prepared tree, the fixed source-owned VGA ROM and a canonical log path; it
has no caller ROM/profile hooks.

The manual workflow is disabled by default, read-only, uses the exact dispatch
commit and pristine pinned Bochs source, and compiles one artifact with the
unchanged closed build helper through a checked derivative. Source, prepared
inputs, Node/header/helper/workflow hashes, raw commands/streams/exits, complete
source archives and licenses are retained even on failure. It never loads the
addon or executes a CPU. Root review and an explicit build grant remain
necessary before dispatch. No build artifact or native success exists yet.

Pure controls validate genuine source-derivative inverses, configuration and
manifest/refusal domains, disjoint fresh roles, source inventory and the
manual gate. Dynamic JS/native correctness execution and actual AX1/AX2
measurements remain the next separate slice; caps are not measured totals.

# Unconnected fixed contained entry preparation

This source-only entry prepares the fixed PID1 limits, then an owned-handle
resource handshake, before reading or executing the fixed controller. The
production `actual()` entry unconditionally refuses before OS, resource, source
or channel work. Its private channel route is unconnected and refuses by default.
External controller approval and metadata are unset; no arming interface or caller
FD, factory, policy, command, URL or pin argument is provided.

The entry captures fixed checkout/metadata/component bindings before hooks. It
hash-loads the exact PID1 preparation module, whose literal CPU 180/180 seconds,
2GiB address space, 64MiB per-file, 256 descriptors and zero core policy is
unchanged. All immediate and final readback facts must satisfy a closed typed
resource schema before anything is sent. These are process-limit facts, not
aggregate or disk quotas, resource sufficiency, namespace ownership or official
host authority. The source loader checks bounded ordinary leaf bytes, identity,
SHA and `O_NOFOLLOW`; it does not prove full ancestor-route ownership or a live
source lease. Full source graph admission remains the controller/observer's
separately reviewed responsibility.

After successful preparation, canonical resource-packet bytes are frozen before
namespace-handle syscalls. The entry opens its local PID namespace FD and PID1
pidfd, retains returned handles before reentry checks, and sends the fixed
`bw.provisioning-contained-resource.v1` JSON (at most 8192 bytes) with exactly two
`SCM_RIGHTS` descriptors. Duplicate handles refuse and are closed uniquely once.
A sequence-packet channel, exact send byte count, five-second socket wait and
exact `ACK\n` are required. Reading five bytes prevents a longer response from
being silently accepted as its four-byte ACK prefix. The old observer does not
automatically admit this new protocol; its integration and independent reader
remain unfinished.

Only after ACK may the exact controller source be read, hash-checked, compiled
and loaded. Its outside-commit approval is not changed by this entry. A minimally
consistent complete/closed result with no first failure and integer-zero cleanup
is required for entry completion; this is not the full independent controller or
official-artifact reader. Returned negative results stay retained and cannot give
completion credit. Captured channel callables and immutable resource/result bytes
prevent later hooks from substituting the admitted packet or reported copies.

Reentry fences surround preparation, send, receive, source loading and module
execution. Cleanup consumes each owned handle/channel close once, preserves the
original primary exception over close uncertainty, and cannot return complete
when final cleanup poisons the lifecycle. Partially installed limit facts remain
available on a failed preparation; there is no rollback or retry claim. Actual
resource limits, observer ownership, outer 480-second timeout, official event/job,
resource sufficiency, archive/toolchain/compiler/guest and performance
qualification remain false or unfinished. No real acquisition is enabled.

Run the pure controls from the repository root:

```sh
/usr/bin/python3 -I -B scripts/i80386-provisioning-contained/controls.py
```

Use the Linux system interpreter matching the workflow, with `os.pidfd_open`
available. The suite mocks that API; its presence does not qualify real handles.

Twenty-one methods mock every resource, PID/privilege, FD and socket edge. They
execute the small limits source against those mocks and use a private tiny fake
controller module, never the product controller. Fixed component pins are not
relaxed by a public API. Controls cover limit/ACK ordering, default refusal,
overlong/no ACK, partial sends, duplicate/partial handles, first-error retention,
set/send/receive/compile/cleanup reentry, frozen packet mutation, negative results
and captured bindings. No real provisioning limits, namespace/socket/process
probe, network, archive, acquired toolchain executable, compiler or guest runs.
The workflow bounds only its own control interpreter. A test-harness global
restoration omission was preserved and corrected; exact source bindings were
not weakened to make those controls pass.

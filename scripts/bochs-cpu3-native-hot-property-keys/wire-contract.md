# H3 per-resume property-key candidate

This source-only derivative authenticates H2 generator and generated C++ bytes. ABI2 exports, native runtime, BWNP1 records, timer phases, callback parameters and return validation stay unchanged. It is not compiled or guest-qualified evidence.

Each validated resume opens a parent NAPI handle scope and creates exactly eight scalar string handles. Scalar callback child scopes borrow these keys; memory/PAGE and other paths retain named-property lookup. The bridge still reads every method or getter from its original object at the original point and invokes dynamically selected functions with the same receiver. It retains no JavaScript function, result, metadata, or borrowed byte pointer.

The RAII destructor clears the active key pointer before closing its parent scope on success or error, before snapshot/return conversion so returned handles never belong to the closed scope. No keys survive a resume, cross threads, or belong to create/inspect/close. Allocation failure denies the resume before entering native code. Unknown keys use the existing named-property path. Numeric validation, detached/shared buffer denial, immediate byte copying, mutex, owner thread, reentry and lifetime checks are retained.

Key setup is outside native_resume_inclusive but inside the caller's whole resume invocation. H2 callback phases and clock-read census are unchanged. Timings cannot omit setup when comparing whole execution. No cached method results or representative speed claim is made. Hostile getter/method mutation controls must be exercised on the built candidate before qualification.

# Fixed archive refusal diagnostics

This source derivative preserves the pinned fixed-alias parser's acceptance
rules and original exception. It adds the first fixed rule label, header ordinal,
decoded header offset, numeric type byte and classified magic. These bounded
primitive facts disclose no names, links, raw headers or bodies. Header extension
acceptance has not been added. Unsupported GNU/PAX types remain refused.

The prior failed materialization original remains unchanged. Its `archive-type`
code does not establish which header type or rule failed. These new facts require
a separately qualified source and original diagnostic; manufactured fixtures do
not identify the original offending header.

The nine-role policy, four authenticated input pins, thirteen fixed aliases and
limits are inherited unchanged. No aliases are written. Compiler execution is
still unconditionally disabled; guest, performance, source ownership, full tool
chain and raw archive compatibility remain unqualified. Offsets count decoded
bytes consumed before the current header, including padding. The first rule is
retained across cleanup; no archive content is exposed through status.

Run the controls only with manufactured archive and filesystem inputs:
`python3 -I -B scripts/i80386-cwsdpmi-archive-refusal-diagnostic/materialize-control.py`.
The inherited runner fixtures supply a manufactured successful nine-role case.

The diagnostic covers the copied TAR rule checks and numeric fields. Inherited
canonical-name, name-field and BZ2 reader refusals retain their original code
with a null diagnostic; this is not universal parser failure coverage.

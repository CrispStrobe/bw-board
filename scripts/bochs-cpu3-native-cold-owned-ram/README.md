# Owned cold RAM source checkpoint

`owned-ram.h` is a proposed C++ ownership core for the fixed A20-on cold map. It copies the complete 1.5 MiB RAM and 64 KiB ROM inputs, creates one full initial RAM shadow tied to a non-reused session identity, and owns reads and writes for ordinary RAM/ROM and open bus. MMIO, paging, DMA, mapping changes and clock authority are outside this profile. The journal holds at most 32 complete write records and refuses a full-capacity write before mutation. The caller must reconcile and acknowledge the copied journal, then retry the exact uncommitted effect. A committed effect cannot be retried. An executed-page write creates a separate post-effect invalidation fence. Observer admission reconciles the full batch before exposing the shadow.

`mock.cc` executes adversaries for whole spans, ROM aliases, overlap, copied batches, full capacity, changed retries, code fences, reentry, failure and same-address session reuse. `test/i80386-cold-owned-ram-source.test.mjs` compiles and runs that C++ implementation. This source checkpoint is **not connected to the Bochs CPU3 callback path** and has no addon or guest result. The current JS callback path remains the oracle.

The next change must add an isolated addon/CPU3 adapter with a copied initial board RAM transfer and explicit journal drain/ack transport. Its first actual owned cold guest fixture should compare against the unchanged callback path, including requested full state, board and RAM, ordered PIO and N/Q. Full cold parity and same-host paired timing are separate gates; this source alone establishes neither.

# Owned cold RAM source checkpoint

`owned-ram.h` is a proposed C++ ownership core for the fixed A20-on cold map. It copies the complete 1.5 MiB RAM and 64 KiB ROM inputs, creates one full initial RAM shadow tied to a non-reused session identity, and owns reads and writes for ordinary RAM/ROM and open bus. MMIO, paging, DMA, mapping changes and clock authority are outside this profile. The journal holds at most 32 complete write records and refuses a full-capacity write before mutation. The caller must reconcile and acknowledge the copied journal, then retry the exact uncommitted effect. A committed effect cannot be retried. An executed-page write creates a separate post-effect invalidation fence. Observer admission reconciles the full batch before exposing the shadow.

`mock.cc` executes adversaries for whole spans, ROM aliases, overlap, copied batches, full capacity, changed retries, code fences, reentry, failure and same-address session reuse. `test/i80386-cold-owned-ram-source.test.mjs` compiles and runs that C++ implementation. `napi.cc` is a separately built companion addon with one session per Node environment; concurrent Workers cannot share its owner pointer. `provider.mjs` routes actual CPU3 memory callbacks through JS into that addon, while keeping the existing CPU3 addon, clock transport, PIO and device callbacks. The provider reconciles the native journal into its JS board memory before every clock, PIO and page observer. The JS drain exposes copied address, generation and before/after bytes only; sequence, effect and N/Q stay inside the native session, which performs the exact contiguous acknowledgement. `test/i80386-cold-owned-ram-napi-source.test.mjs` exercises copied bytes, journal records and concurrent Worker isolation. This proves a distinct C++ ownership/coherence profile, not direct CPU3-to-owned-RAM memory calls.

`test/i80386-cold-owned-ram-admission.test.mjs` holds a native write pending while malformed clock tapes, invalid ROM pages and scalars, callback reentry and forbidden PIC ACK are refused. It checks that refusal does not drain or acknowledge the journal or change board RAM, page generation or N/Q. The completed clock tape must satisfy `Q <= N`; a valid tape may begin with Q and later carry N. The prior provider fails this adversary by acknowledging a write before rejecting an invalid reason. Stateful board PIO errors after otherwise valid argument admission remain outside this assertion.

`actual-fixture.mjs` runs the bounded guest with either the new owned provider or the unchanged callback provider. `compare-fixtures.mjs` requires exact reset, requested last and final native records, complete board state, whole final RAM hash, ordered PIO records and N/Q equality. A local diagnostic using the previously built CPU3 addon passed the complete cold target: 316,562 N/Q, 16,524 resumes and 16,475 ordered PIO events. Both sides requested the full 166-word reset, last and final state and closed their sessions. This is a local actual guest result; the dedicated workflow repeats it at an immutable hosted head with retained evidence. Independent review remains necessary before adoption.

The fixture executes ROM pages only. MMIO, paging, DMA, mapping changes and executed RAM code writes fail closed; another profile must add an explicit post-write code invalidation acknowledgement and prove its larger scope. Direct CPU3 memory calls and an explicit clock lease are further integration work. This companion bridge still crosses JS for every memory callback and may add crossings; it establishes no speed gain. Same-host paired timing is a separate gate after a measurable optimization exists.

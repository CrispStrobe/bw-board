# Guarded word-fetch public paired measurement

This separately named fixture measures the authored 24-form code16 macro through ordinary `I80386.step()` and a real byte-memory bus. It uses no BIOS, disk, private input, native backend or execution accelerator. The complete work unit is 100,000 host passes of 24 MOV AX,r/m16 instructions: 2,400,000 retired instructions, eight million fetched bytes, 4.8 million read bytes and no writes. Host EIP rewind, loops, scalar work checks, source admission and final hashing are included in the whole Node process interval. Model step units are not calibrated physical clocks or RTx.

The independent oracle covers all memory ModRM forms, direct mod0/rm6, signed displacements, wrap, default DS/SS and six overrides without overwriting BX/BP/SI/DI. It freezes physical addresses, fetched/read byte counts and final CPU/memory checks. The fixture rejects stopped/faulted engine state and nonordinary profile/cache settings before emitting a result; the zero error count follows successful uncaught step calls, not an invented engine fault counter. Tiny controls test exact byte-bus order and faults; the timed path records numeric counters rather than allocated instruction traces.

The fixed source contexts are A `c847c0470cfaf4ad3c781ce7a83a35b939497533` and B `e2c537affb6e0e56194429723abeb356095a3607`. Every one of the 43 selected source rows joins Git and live bytes, including each package.json; only the CPU source differs. The Node executable is authenticated once and rechecked before and after each child. The new common fixture, runner, policy, controls, README, fixture test, workflow and publication package.json are separately authenticated against the exact publication commit. They cannot differ between arms.

The dedicated workflow runs only on pushes to its implementation branch, in the own repository and first attempt. It does not duplicate a pull-request or dispatch measurement. Ubuntu 24.04 and Node 20.20.2 are fixed. An owned systemd service applies one logical CPU/cpuset, cgroup-v2 cpu.max `100000 100000`, memory.max `1073741824` and memory.swap.max `0` to the Python wrapper and all Node children. The source reads actual membership, limits and affinity before every child and inside its pre-exec setup; it refuses unavailable enforcement. There is no 1 GiB address-space rlimit. The service has a 23-minute lifetime inside a 30-minute job; children have a 60-second source deadline. The systemd client is not the measured process. An always-running workflow step retains exact unit state, stop result and owned cgroup empty/absent observations; a client timeout does not prove cleanup. Failure or speed-gate rejection remains failed even when cleanup succeeds.

Four warmups run ABAB, followed by seven pairs in AB, BA, AB, BA, BA, AB, BA order. The runner harvests each owned child's wait4 usage once: user plus system CPU and matching monotonic wall. Raw child stdout/stderr, timing and resource facts remain in fixed per-child directories. Timeouts, missing rows, source drift, resource uncertainty or semantic differences stop the sequence without retry or replacement. The speed gate requires median CPU speedup at least 1.03, all seven CPU ratios above one, and median candidate/baseline wall at most 1.02. Every ratio and the conditional 99.21875% minimum-ratio bound is reported with its independence/continuity/exchangeability assumptions.

Correctness controls are `node --test test/i80386-fetchn-paired-fixture.test.mjs` and `/usr/bin/python3 -I -B scripts/i80386-fetchn-paired/controls.py`. Seven fixture tests and 21 policy/mock controls pass. The workload algorithm and oracle are copied from immutable publication `7803a6341d319b30da2bcd4065e5c8005940687f`; only admissions and experiment/schema names change. This compares the ordinary baseline with the isolated word-fetch candidate, not the scalar address-decoder candidate. These run only tiny passes and mocked process/resource policy cases. Source review and controls are not an actual paired measurement. The hosted capability and the first original 18-child result must be independently audited; no performance gain is currently claimed.

A pass is limited to this authored public workload. It does not replace the original benchmark gate, qualify adoption of the performance-only CPU change, claim operating-system compatibility or enable another backend.

# Pending finite native page-fault ledger

This first source slice proposes a separate native fault-aware protocol for the owned page-fault fixture. It does not alter the qualified INT/IRET, paging, stack or cold profiles, the ordinary JS CPU, ABI 4, or the five arrays containing 166 native words. No native runtime, build, addon or guest is admitted by this source policy. Tests had not run in the original source proposal.

The existing authenticated ABI 4 result is 160 bytes. It directly exposes reason, charged N/Q, source attempt/completion/fault counters, pending-fault/vector/error/CR2, and the **returned** CS:EIP. `bw_fill_result` reads current CPU CS:EIP after delivery: for this fixture that is 18:7020, not the interrupted 18:7003. No direct interrupted-owner field exists. The byte decoder checks all documented field offsets against the copied snapshot and retains pending-event telemetry without inventing its value. The existing held runtime unconditionally calls `cold-BIOS-no-fault`, so a distinct reviewed fault-admitted runtime/profile and fresh DSO are prerequisites to any real test.

The chosen owner proof is explicitly **source-attested inference**, using a source-authenticated paused full snapshot before 18:7003, exactly one requested N/Q, exactly one additional attempt and fault, N +1 / Q +0, FAULT reason 2, direct vector 14/error 2/CR2 8000, returned 18:7020, and the actual eight-byte frame at physical CFF8 (`02 00 03 70 18 00 02 00`). The fault boundary requires all ten full pages: failed data remains unchanged, the PTE is still nonpresent, and the exact frame and final IDT/stack A/D effects exist. Future native fault-note ownership must also guard genuine `bw_attempt_cs/eip` and `prev_rip` before delivery; this policy is not a replacement for that native gate.

The finite post-fault sequence is ordinary PTE installation, EDX CR3 read, same-CR3 reload, ADD SP,2, IRET to the real restart IP, exactly one successful retry store, and readback before HLT. The ledger keeps N, completed Q, attempt ordinal, fault serial, API resume count and prefetch-return count separate. A zero-N/zero-Q return cannot admit a fault or attempt: it is labelled unmatched, without claiming page parity. The policy consumes caller snapshots/pages but does not persist them; the future differential driver must retain them in full. Comparable fault/ordinary phases check all ten whole physical pages without masks. No JS/native page-walk callback order or generation equivalence is required.

The CS, DS and SS rows are separate native source expectations: CS valid 1; loaded DS/SS valid 1; failed write checking and real frame stores produce DS/SS valid 7. These are grounded in the prepared Bochs CPU3 segment-check/write paths, remain unobserved for this new fixture, and are not a mask over possible mismatches. All snapshot words remain raw. The finite helper does not claim full cross-engine parity: a future driver must compare all represented CPU counterparts and board state as well as retain native-only fields.

An external alternative would append interrupted CS/EIP to a **new** 168-byte supplemental result with distinct authority and fresh build; it would leave raw166 and old ABI 4 untouched. It is unnecessary for this narrowly owned before/frame proof and is not implemented here.

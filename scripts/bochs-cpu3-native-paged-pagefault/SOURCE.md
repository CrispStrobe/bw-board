# Fixed page-fault recovery and retry source proposal

This separate finite profile is a source proposal. Its tests and private JS oracle have not run at this checkpoint. There is no native preparation, build, DSO admission or native page-fault execution. The previously qualified [INT/IRET result](../../docs/I80386-PAGED-INT-IRET-RESULTS.md) and all held CPU/profile/driver policies remain unchanged.

The owned program uses strict 386, CPL 0, 16-bit code and 4 KiB paging. Linear code 7000 maps to physical A000, initial data 8000 is nonpresent and will map to B000, and stack D000 maps to C000. GDT 0000, directory 1000, table 2000 and IDT 3000 have fixed mappings. The ten copied physical pages include poisoned 7000/8000/D000 aliases. The fixed ROM sets up accessed descriptors (CS 9B, DS/SS 93), an actual type-6 vector-14 gate at 3070 targeting 18:7020, IDTR limit 0077 and ESP E000. PG is enabled in the authenticated identity ROM transition before the far jump to nonidentity code.

`MOV AX,1234` preserves the EAX upper half from the explicit PG setup. The first `MOV [8000],AX` at 18:7003 must genuinely fault with vector 14, error 2 and CR2 8000, leaving B000 bytes `78 56 9A BC` intact. The genuine translated eight-byte frame at CFF8 is `02 00 03 70 18 00 02 00`: error, restart IP 7003, CS 18 and FLAGS 2. The private factory wraps the ordinary fault and delivery methods only to verify the fixed owner and returned state; it calls the originals and never constructs a frame or changes post-step state.

The handler executes ordinary instructions to install B003 at physical PTE 2020, read CR3 into EDX, reload unchanged CR3 1000, discard the real error word with `ADD SP,2`, then IRET to 18:7003. The store retries once, committing 1234 at B000; readback into CX follows, and the oracle stops at 18:700A before HLT. EAX must remain 80001234, EDX 1000, CX 1234 and ESP E000. ADD's defined flags are checked against the actual instruction's result at its cut (the source expectation is 86); IRET restores the real saved flags 2. No flags mask or post-step normalization is used.

CR3 reload is deliberate. Authentic prepared Bochs `crregs.cc:1389–1397` flushes even unchanged CR3; `paging.cc:384–403` invalidates prefetch, stack and translation caches. The held ordinary JS CPU invalidates its translation generation on CR3 writes. INVLPG is excluded because Intel documents it as unsupported before Intel486 in the [instruction reference compatibility section](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf). No CR4/PSE extension is permitted. Recovery from a nonpresent page does not itself prove stale-positive-translation invalidation.

Attempt ordinal and successful Q are distinct. The genuine JS faulting step restores the instruction registers, retains CR2, delivers the actual fault and returns zero, with no successful-instruction board charge. One fault serial makes `attemptOrdinal = Q + 1`; all other ordinary steps increment both. Callback tapes label their actual attempt ordinal and Q before completion. The real failed store and retry have the same CS:EIP and different fault serials; they cannot share an ambiguous milestone name. The oracle refuses a second fault, any alternate vector/error/restart address, duplicate repair or duplicate committed retry, external interrupt, PIO, early settle and HLT execution.

The prospective native driver must recognize exactly one FAULT reason (2) with N+1/Q+0 and raw fault metadata before running the one genuine JS zero-completion attempt. Prepared `cpu.cc:60–70` yields after exception delivery and before the first handler instruction; held runtime fault-clock guards enforce N+1/Q+0. Generic zero-Q prefetch returns cannot trigger fault delivery. The old cold/INT no-fault guard and N=Q fixture remain immutable; new native policy, generated roles, build context and fresh statically audited DSO are required later.

Every actual JS attempt records its complete represented CPU state, full board, all ten copied 4096-byte pages, actual stores, A/D updates, fault delivery, translation-generation reload and memory reads. Whole pages are reconstructed only from the allowed boot, frame, handler, retry and A/D writes. The first failed data store must not commit; ordinary handler PTE installation is separate from page-walker A/D updates. Code/IDT/GDT/ROM PTEs cannot become dirty; table, stack and successful data leaves finish 2063/C063/B063. JS's eleven source-expected A/D transitions are checked with exact owners. Future native combined A/D writes, generations and descending push order remain independent tapes rather than a forced copy of JS order.

Native cache expectations remain source hypotheses: DS valid 1→7 before the first faulting store's translation, and SS valid 1→7 at the first actual frame write. The prepared chain `cpu.h:5341–5360`, `access.h:190–193`, `access.cc:82–102`, `access2.cc:53–77` checks the writable segment before paging. These are not observed native PF phases. A later driver must keep strict native descriptor rows separate from JS-represented counterparts, retain all 166 raw words, and never confuse selector index with cache valid. JS MOVSS returns shadow 1/1/0, followed by MOVSP zero; native inhibit is a separately source-attested phase.

Seven proposed controls comprise five manufactured/source policy cases, one actual factory/reset/stage case with zero instructions, and one separately bounded genuine private JS fault/repair/retry program. Encoding, ROM pointers, gate, all 31 structural boot stores and every handler byte are source-proved; instruction counts come from the later capture, not a guessed native Q. Source identity includes the ordinary dynamic CPU bytes and full relative import closure with clean current/Git equality. A reviewed external bounded parent must pin the frozen source/Node/tools, retain raw failures and before/after maps, and write the actual capture outside the checkout. No control is authorized by importing this module alone.

The fixed program is freely distributable owned code. This proposal makes no broader software, physical 386 speed, performance or adoption claim. Copied host pages and whole-RAM hashes must keep their usual explicit scope. Later native comparable cuts will compare unmodified full pages/full boards; unmatched PG/prefetch/zero-Q phases stay intact raw records, never silently masked into parity PASS.

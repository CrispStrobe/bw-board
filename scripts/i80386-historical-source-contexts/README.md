# Fixed historical source context helper

This first slice implements bounded metadata and context-consistency checks.
Actual materialization, Git/readback operations, context release and JavaScript
import routes are unconnected source-owned stubs. `actual()` and the default
`Context()._prepare()` refuse before metadata, filesystem or Git work. No external
seal, caller root, commit, code, module, command, environment or factory parameter
arms these routes. The ten existing test harnesses and workflow remain unwired.

The immutable table contains186 relative source/data roles at public commit
c3ada315e9dfc51cd70ac6403d9e1ab18a0faf5c, each with Git blob, extent and SHA256.
The exact ten selectors choose only81 held support-module import roles. Historical
test files are hash inputs, never auto-imported. Two free BIOS/VGA files are read/
hash inputs of PIC source admission, not executed firmware. Repository MIT and
free-at-bios LGPL notices and profile attribution remain in the table.

The original-proof descriptor retains four original41-source JS maps and their
own historical commits, the exact compiled PIC111/a6 map and four native fixture
encoded/decoded pins and original commits. The compatible context does not
replace those original source identities or authenticate the original historical
runtime. The only existing PIC live-input allowance is package.json; no CPU
waiver is introduced. Native decoded report validation still belongs to unchanged
held comparators; this helper does not claim to have replayed or revalidated them.

`Context` has no constructor arguments. Private `_prepare()` captures source
bindings, authenticates both fixed metadata digests, validates closed rows and
selectors, checks mocked owned context head/repository/detachment/cleanliness,
and joins all186 Git/source bytes, including independently recomputed Git blob
hashes. Four original JS maps and compiled PIC111 use their own commit joins.
All bodies are admitted before `_load(group)` can reach its fixed support-import
stub. A detached boundary copy cannot rewrite the admitted row map. Failed
preparation consumes the returned owned capability through its captured release
route once, preserves the first exception and records secondary cleanup refusal.
The original returned capability is an exact immutable tuple of head, repository,
detached/clean observations and bounded internal token. Every Git/read/import/
release path retains that original capability even if a boundary changes the
public working field. Importer, groups and native hash constructors are captured
before admission hooks; each owned hash call is fenced against reentry. This mock
capability is not a source ownership proof.

Preparation/import consistency flags in tests are not actual materialization,
historical runtime, current CPU or native qualification. Modern Node/binutils
revalidation is a separate hosted observation. Existing held same-engine replay,
when later wired, requires those exact sources and public history objects.
No new binary, guest, compiler, performance or licence clearance follows.

Controls: `/usr/bin/python3 -I -B scripts/i80386-historical-source-contexts/controls.py`.
Seventeen manufactured controls use tiny repeated authored bytes, privately patched
metadata seals and mocked materialization/Git/readback/import/release. They never
create a real worktree, invoke Git or binutils, import held JavaScript, or run a
guest. The first control fixture stopped earlier at a contradictory native blob
row than its cleanup expectation; it was corrected without changing admission.
Source preparation remains gated on independent review. Production loaders,
current CPU, original receipts and historical pins are unchanged.

# Fixed historical materializer source

`materializer.py` adapts the unchanged `Context` consistency checks to a fixed Git provider derived from this namespace. It admits the 186 held rows, four original JavaScript maps, four native execution commit objects and the PIC111 original map before issuing an owned context. Encoded native captures are joined to the compatible context rows; their execution source commits are not misidentified as capture publication commits. Native decoded source-map validation remains in the held comparator. It accepts a shallow provider when those exact objects are present. It never fetches or clones missing objects.

The adapter creates an owned temporary detached context at the fixed held commit. It writes exact sparse patterns into the owned worktree Git directory and passes sparse settings per command; it does not enable worktree configuration in the provider. Before checkout it rejects nonregular tree modes, tracked attributes, local conversion/include configuration names and an `info/attributes` file. Configuration values are not retained. Global/system configuration, hooks, conversion defaults, network protocols and lazy fetching are disabled for its Git operations.

Live reads open directory components and leaves without following symlinks, retain directory descriptors through the read, and compare held and named identities and exact extents. Final release checks the index, all untracked files (including ignored files), and every held byte hash. Removal is confined to the captured owned parent and context identities. A failed add can leave an empty unregistered directory; its cleanup also checks that registration is absent. Partial nonempty or substituted contexts produce cleanup uncertainty. Successful removal does not erase an earlier readback failure.

Git calls have bounded stdout/stderr and cooperative per-call waits. The startup budget is 120 seconds; later final checks do not inherit a lifetime-wide startup deadline. Cleanup signals only an unreaped original child process group. A reaped leader does not grant a descendant cleanup lease. These checks are finite source observations, not a hostile-process boundary, continuous ownership lease or externally enforced whole-session deadline.

The default `Context`, import route and `actual()` remain unconnected or unsealed. No Node bridge, ten-harness wiring, assembly, emulator, guest or workflow integration is included in this slice. Adapter observations remain separate from the unchanged model flags. Historical runtime and current CPU qualification remain false.

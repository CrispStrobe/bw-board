# Source-only masked PIC IMR fixture

This prototype inherits frozen fe1's 103 source files unchanged and adds eight source files. It has no native addon, actual guest result, performance result or default API change. The fresh-child IN8 production runner and PIT fixture remain untouched.

The new 64 KiB ROM hash is `8a7380f01bbc40985d377fe9764667749c36b05d45ee602b28c7e68556bd509f`. After the existing master/slave ICW initialization, the guest leaves CLI active, masks both PICs with `0xff`, reads IMR at `0x21` and `0xa1`, writes the two returned bytes at `0x592` and `0x593`, then restores master IMR `0xfe` before the existing PIT/fault/IRQ workload. Expected bytes are `[255,255]`. Original PIT witnesses `0x590–0x591`, marker, register/memory loops and two-fault/one-IRQ assertions are retained, but instruction totals, six selected Q cuts and whole-RAM hashes require a new real JS reference. Original 445-resume/native totals are not asserted for this ROM.

The provider is the actual factory-owned ABI4 IN8 owner with only its assembly source, fixed ROM hash, factory name and additional terminal witness changed. Byte width/port guards, typed byte/epoch/A20 reply, mapping/lifecycle checks, pre-PIO flush and mandatory post-PIO query remain exact. No PIC poll/ACK reads or new ports are admitted. The native runtime derivative changes only the initializer's expected ROM hash, with exact inverse proof. Future native preparation must bind this derivative and ROM consistently; the old PIT addon cannot initialize this ROM. No preparer/build admission is implemented here.

`I8259.read(1)` returns IMR without PIC effects when `pollPending` is false. Armed polling consumes and acknowledges a request even on a data port. The owner therefore refuses an armed target before PIC read/ACK effects; the preceding native tape flush may already have committed clocks. There is no rollback claim. Source controls retain full target and peer PIC states, clock/debt ledgers, and mapping at denial. The JS reference runner will capture complete PIC state immediately around each actual model read, after clock catchup, and require it unchanged; those diagnostic snapshots do not assert clock catchup itself is side-effect-free.

The baseline runner is prepared only and must run once at a clean frozen 111-source identity under bounded process containment after authorization. It retains all journal events, reset/final CPU/board fields, six named boundaries, whole RAM, all PIO values and full PIC read observations. The existing explicit EDX/CR0 reset profile remains a comparison policy; its old canonical RAM anchor is not reused for this distinct ROM. Future native mode proof must preserve all native words and compare exact newly measured fields before any qualification.

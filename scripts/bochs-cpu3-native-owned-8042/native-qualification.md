# Fixed 8042 native qualification preparation

This separate candidate prepares a new addon for the exact `b8274e345a5585d2226f982003d1479004cf7f2fb296003caf45e73b3775018f` ROM. It admits only the fixed real-mode AA/status/55/FF/K/HLT handshake; IRQ, fault delivery, REP and RAM execution are denied. Original compiled fe1 and all earlier speed candidates remain unchanged.

The [PR-only workflow](../../.github/workflows/i80386-native-owned-8042-build.yml) checks out the exact reviewed source head and pinned pristine Bochs, compiles one new addon, authenticates source/build/configuration before loading it, and runs separate OFF and ON children. Each child uses CPU 30 seconds, wall 60 seconds, heap 128 MiB, core zero, nice 10 and six empty hook variables. Both native totals are capped at 512; every resume admits one N/Q and stores all 166 native words and the whole actual board state. Raw streams, incomplete captures, exits, maps, prepared sources and licenses survive failure. There is no automatic retry or performance gate.

The independent ordinary JavaScript reference measures all instruction cuts, actual PIO ownership/timing, whole controller/PIC/board state and the whole final RAM SHA. Native OFF/ON must match all 166 words at reset, every instruction and terminal. Native/JS checks cover exposed architectural fields with explicit model reset profiles. Native hidden words have no invented JS counterpart; the comparator records the exact exclusions. PIO trace comparison uses native completed-N versus JS attempt minus one. No host journal is claimed.

Bochs CPU3 reset literals differ from this JavaScript model: EDX `0` versus `300h`, CR0 `7ffffff0h` versus `0`, GDTR/IDTR limits `ffffh` versus `0`/`3ffh`, LDTR/TR presence and limits, and DR6/DR7 reserved bits. The ROM never changes them; both raw literal profiles are checked at every cut. The [Intel 1986 manual, section 10.1](https://www.ardent-tool.com/CPU/docs/Intel/386/manuals/prref386/s10_01.htm) specifies reset IDTR limit `03ffh` and DH `3`; the Bochs differences are oracle-profile deviations, not hardware corrections. Both logical reset CS bases are `ffff0000h`; the board's `ff0000h` backing alias is a separate physical decode rule.

Three bounded source reference/refusal tests pass, including the actual 28-step JS handshake and mutation refusals for every raw native word. The first test failed because generic byte PIO hooks omit width metadata; the corrected reference explicitly records that source byte width, and the original failure is retained. C derivation controls are separate. Actual hosted build/native results remain pending independent artifact audit; no native qualification, speed result or broader AT/Windows/Doom admission is claimed by this preparation.

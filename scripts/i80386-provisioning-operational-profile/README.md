# Connected operational provisioning smoke

This profile connects the existing contained Entry, PID1 Limits, SCM_RIGHTS
resource/handle transfer, receiver's five readonly `prlimit` readbacks, ACK,
Controller and Lifetime without changing those sources. The fixed smoke leaves
the genuine Controller approval seal unset: after ACK it must refuse with
`approval-unarmed` before any transport or acquired tool execution. A zero
smoke exit means that expected refusal was captured, not provisioning success.
The public `actual()` entry always refuses and compiler execution is disabled.

The default driver seal is unset and refuses before graph admission, report
capture or process launch. Module path initialization is not that admission.
After independent source review, the launch owner supplies one exact external
review blob and digest in the owning PR body. The dedicated own-repository PR
workflow verifies the verbatim blob, exact head and driver bytes, then binds its
digest on a fresh module. The digest covers only reviewed source graph facts;
run/attempt and installed tool identities are separately observed eligibility
facts. They are not a job-created independent approval or an actual once gate.
The owning reviewer, repository, branch and attempt are fixed workflow guards.
Only the initial `opened` PR event may launch the smoke; edits, synchronization,
reopening and attempt reruns cannot launch another real smoke.

The external review has closed schema `bw.provisioning-operational-approval.v1`:
`schema`, `repository`, `head`, `mode`, `roles`, `graphSha256`. Mode is exactly
`limits-ack-approval-refusal`; repository is `CrispStrobe/bw-board`. Roles contain
exact bytes/SHA-256 rows for every path listed in `fixed-graph.json`, including
the graph itself and this workflow. The graph has no own-hash row: its digest is
in the outside-commit review. All held rows must match their immutable pins.
The external review marker is
`<!-- bw-provisioning-operational-review-sha256: DIGEST -->`, followed by one
fenced `bw-provisioning-operational-review` JSON block. The digest covers the
UTF-8 block bytes including their final LF. Only the launch owner adds it after
source and control audits; ordinary pushes use the existing repository checks.

The root timeout begins before ownership preparation of the fresh task-only,
full-depth, detached Actions checkout and before driver bootstrap. No shared
checkout is changed, no `safe.directory` exception is added, and held Git
configuration remains scrubbed. The observer is under a separate 488-second
timer; its contained command is root timeout 480 seconds, unshare PID namespace
and fixed system Python. Root privilege is acquired before endpoint creation;
there is no inner sudo or credential drop. Child environment explicitly includes
the three eligibility fields required by Limits. Host/kernel/tool/source trust,
continuous leases, resource sufficiency and the complete official once/run gate
remain separate qualifications.

Only the internally created channel and report-directory descriptors pass to
the child; stdout/stderr originals map to descriptors 1/2 and stdin is DEVNULL.
The exact original resource packet is retained before send. Entry owns its
channel close, so structured reports use a separate owned directory. Controller
status is first serialized after its original finally, using Entry's retained
real instance. Failure-only Controller capture never pretends Entry issued a
successful `controllerResult`. Entry projection excludes that nested result;
Lifetime projection removes only binary prefixes into unchanged raw roles.

The separately versioned companion has eleven fixed possible roles. The outer
observer's diagnostic is distinct from child stdout/stderr. Per-role maxima are
Controller 256 KiB, Entry 64 KiB, original resource 8 KiB, readbacks 16 KiB,
Lifetime 32 KiB, final index 16 KiB, event 8 KiB, three raw streams 64 KiB each,
and optional unchanged observation ZIP 512 KiB. Their sum is 1,130,496 bytes;
decoded cap is 1.5 MiB and companion ZIP cap is 2 MiB. Partial files are retained,
not deleted to manufacture captured status. One parent finalizes the index after
all reports. A bounded internal child journal is separate staging evidence.
The original held nine-role observation format is unchanged; this early smoke
has no genuine child source-before, so no observation ZIP is issued.

The independent reader consumes bounded bytes without producer imports. It
requires literal resource policy/readbacks, ACK, expected original refusals,
terminal admitted PID1, launcher reaping, two empty censuses, original raw byte
joins and zero uncertainty for `finiteFixturePass`. It always reports false
acquisition, materialization, compiler, guest and performance qualification.

Run source-only controls on Linux system Python:

```sh
/usr/bin/python3 -I -B scripts/i80386-provisioning-operational-profile/controls.py
```

The 38 controls use tiny authored report bytes and ordinary owned temporary files.
All process, namespace, socket, PID/credential and resource-installation edges
are mocked; no real provisioning PID1 policy or namespace is altered locally.
They include unchanged Entry/Limits/Controller composition with mocked kernel
operations. Genuine host wiring must pass the separately reviewed PR smoke;
local controls do not establish it. Original failures are retained in private
review evidence, with no claim that this source bundles those receipts.

The Actions upload is an outer transport artifact containing the canonical
`companion.zip` and separately declared raw staging copies. It is not itself the
eleven-role ZIP. Original acquisition must admit that outer member inventory,
raw/decoded caps and copies independently, then audit the inner framing and
cross-join matching raw members. The external approval is a staging copy, not
an operational authorization or source position. Tool observations include Git
used for head admission but do not claim interpreter/library or all-tools closure.

The proposed outer upload admission is at most fourteen fixed filenames:
`companion.zip`, eleven companion raw roles, `approval.json` and the internal
`child-capture.json`. Apply independent 4 MiB raw and 4 MiB decoded wrapper caps;
these wrapper caps do not relax the inner 2 MiB / 1.5 MiB limits. Missing staging
files are genuine absence, and duplicate inner/raw copies must be byte-equal.

## Post-execution artifact read access

The first hosted refusal smoke completed its privileged step, but its artifact
upload failed when the job user could not read the root-owned output directory.
That failed run has no official artifact; it is preserved without a retry or a
packet reconstructed from its console.

The handoff revision keeps root ownership and mode 0700 throughout execution.
Within the same enclosing timer, the source-issued final capture index must
record a returned observer and no outer capture, overflow or cleanup uncertainty.
The verified helper borrows the retained directory descriptor and its original
identity. It reads only the fourteen fixed possible filenames under their exact
caps, requiring root-owned ordinary files with link count one, bounded content
and matching held/named identities. It changes no source or checkout ownership.

Only after the full inventory is checked does it set each file to mode 0444,
observe that mode, and close its owned file descriptors once. Mode 0555 on the
same directory is last, after file cleanup succeeds. The parent checks the named
directory against the retained identity again and closes its own descriptor.
There is no recursive permission change, chown, deletion or arbitrary path API.
Partial permission changes remain visible on refusal; rollback is not claimed.

Unknown freeze or cleanup refuses handoff. A known terminal semantic refusal can
retain bounded diagnostic bytes, while its original driver error stays primary
if handoff also fails. Read access is not materialization, source ownership,
continuous identity, host or official-artifact qualification. A fresh reviewed
head and initial PR-opened event are required; earlier runs are not replayed.

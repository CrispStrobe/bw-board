This is unexecuted source preparation for one closed native reset→before F000:E16 diagnostic against a separate fixed Bochs-reset JS model. It is not native qualification, general AT boot, Intel reset correction or performance evidence. The authenticated ordinary JS reference at executed `60a9b11a` and its raw baseline remain unchanged. The [actual cold static build](../../docs/I80386-NATIVE-COLD-BIOS-BUILD-RESULTS.md) is a separate prerequisite, not proof that this driver reaches E16.

The compiled checkout is fixed at `a6fae61a549d595c88a324f50589d92497040c07`. Its complete original source inventory, generated C/NAPI, prepared Bochs tree and genuine addon are authenticated through its unchanged admission module. The external driver/oracle/comparator are frozen and authenticated independently, so unrelated driver changes do not imply a new compiled C build. A new materialization receipt must distinguish restored filesystem bytes from the original hosted build provenance. Node, driver source/Git, compiled source/Git and original artifact/helper pins require before/after checks in the bounded outer harness, including failure/timeout. No restoration, addon load or guest is authorized by these source files alone.

The private no-argument JS oracle installs Bochs CPU3 reset values once, before any instruction: EDX0, CR0 `7ffffff0`, table limits `ffff`, present LDTR/TR limit `ffff` with types2/11, DR6 `ffff1ff0` and DR7 `400`. These derive from prepared `bochs/cpu/init.cc` SHA-256 `4bdf4a39a2a3ceecafdd070836a055b5dec8696acf59652e2150a12fdfa7a9f3`, lines705–874. Its other reset registers/selectors/caches already match the represented Bochs values, including CS base `ffff0000`. JS code/readable/writable flags retain their own semantic meaning. Subsequent writes, pushes/restores and raw RAM follow actual JS execution; no output normalization occurs. CR0 must remain its reset literal at actual boundaries. Later MOVCR0 semantics differ in reserved-bit handling and require a separately justified profile; this reset-only proposal does not repair them.

Paused `stage()` flushes actual chip debt only at the real deadline and stages the genuine PIC line. IF remains clear; an asserted PIT line is preserved without acknowledgement or masking. The driver pairs that stage with the compiled provider, calls `setIRQ` only on a real line change, then `begin`→`resume(1,1,UINT64_MAX)`→`end`. N and Q stay independent. Only returned Q delta1 advances the JS core; delta0 stages without executing another instruction. Total native N/Q remain capped400k and total resumes800k. The normal terminal is paused CS:F000/EIP:0E16, before executing E16; HLT/IRQ/fault is a failure. Final settlement catches up actual devices without rearming, then hashes whole raw RAM and closes both owners. Native create accepts the authenticated configuration **file path**: pinned bootstrap supplies it to Bochs `-f`; it does not accept configuration text.

Every returned native snapshot contributes all166 uint32 words plus all returned metadata to an ordered constant-space digest. Represented architectural counterparts are compared dynamically after each returned boundary. Full actual board state is compared at stage effects, PIO, the fifteen named cuts and final settlement; matched non-cut states are source-attested comparisons/digests and cannot be independently reconstructed from this output. No 316k snapshot array or 16k full-board cut array is retained.

Only fifteen named raw CPU/full-board cuts, four REP entry/exit records with actual JS element metadata, whole ordered PIO tapes and the first divergence are retained. The provider has no paused RAM-range API: native before/after bytes for each REP element are not observed.

# Owned CWSDPMI client: QEMU-only control

This profile runs the [owned DJGPP client](../i80386-cwsdpmi-owned/client.c) once in FreeDOS 1.4 with the SHA-pinned CWSDPMI package. It first compiles the client with the authenticated toolchain and source archives from the [compile-only profile](../i80386-cwsdpmi-compile-only/README.md). The guest is QEMU TCG `pc`/`486` with 4 MiB of RAM, SeaBIOS and standard VGA. The later board AT run is a separate acceptance gate. This profile does not claim strict 386 hardware behavior, full state equivalence, real mouse operation, or performance.

The one QEMU invocation must show a current FreeDOS prompt before each command. The first command runs the client, writes a guest errorlevel-zero marker, and returns to the current prompt. The second command writes a distinct return marker and again reaches the current prompt. The redirected guest output must contain the exact `BW_DPMI_OK checksum=4225408` line once. The evidence retains raw 4000-byte VGA snapshots, FAT result bytes and hashes, the initial/final disk hashes, selected QEMU/BIOS/VGA identity, command and cleanup receipts. A marker or loader banner alone does not pass. Internal INT 2Fh/31h service order is not observed by this QEMU control; source-bound AT instrumentation follows later.

The dedicated labeled workflow admits its exact same-repository PR head and inherited source roles before fetching inputs. It fetches only pinned component archives, builds internally, and uploads bounded reports, logs, notices and small screen snapshots. Compiler, client, host, floppy and hard-disk executable/image bytes stay out of the artifact. A failure preserves the first reported cause and available partial disk/screen evidence. Source controls exercise archive, media and oracle grading without compiling or booting a guest. Until the hosted workflow passes at a reviewed head, this is source-only code.

This separate source proposal extends the fixed ring-0 code16 RAM entry to an accessed writable DS/SS descriptor, a register PUSH/POP and one near CALL/RET. It stops before HLT. IF stays clear, paging stays disabled, A20 stays enabled, and faults, IRQ delivery and PIO are refused. No native build, admission or execution is provided by these files.

The private no-argument oracle reuses the authenticated reset initializer and the one-seam MOV CR0 derivative from the protected RAM source proposal. These are explicit Bochs CPU3 model semantics, not Intel hardware corrections or post-instruction normalization. Ordinary CPU and previous qualified profiles remain unchanged.

The ROM installs the two already-accessed descriptors and exact RAM program. Full GDT, code and stack pages are checked after every instruction against only the ordered authorized effects. PUSH writes 1234 at 8ffe; POP recovers BX. CALL replaces that word with the authentic return IP7012, the callee writes AXabcd, RET restores SP9000, and the return path writes CX5678. Descriptor cache fields represented by JS are checked separately from native-only hidden words.

MOV SS creates the existing JS core's interrupt/NMI shadow for one following instruction; its returned state is [1,1,0], then MOV SP clears it to [0,0,0]. These exact phases require a separately reviewed native policy later. No blanket shadow or descriptor exclusion is proposed. Caps are maximums, not measured native instruction counts. This is a correctness stepping stone; no OS coverage, performance or adoption claim is made.

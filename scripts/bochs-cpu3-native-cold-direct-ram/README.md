# Cold CPU3 direct-RAM source/control checkpoint

**Unintegrated.** This directory defines an ABI 5 model and bounded C++ controls for a future same-DSO CPU3 RAM/ROM owner. It is not connected to CPU3, N-API, the JavaScript board, or a guest. The existing companion addon and ordinary JS path remain unchanged. No guest parity or speed result follows from these controls.

`bridge.h` compiles the existing `bochs-cpu3-native-cold-owned-ram/owned-ram.h` into the same C++ model. `abi.h` pins the companion header SHA-256, profile, extent and journal capacity. A Session copies the initial 1.5 MiB RAM and 64 KiB ROM, and a unique full-initial Shadow belongs to it. The Bridge admits a single 16 MiB board view with a distinct generation view, and copies its four object/buffer identity tokens; borrowed byte pointers are used only during synchronous binding or commit. A future N-API wrapper must supply actual object identity, rather than caller-selected tokens.

Each memory request is checked against fixed A20, ROM/open-bus/RAM decode, the complete one-page span, source-validated N/Q, exact next effect, owner sequence watermarks and generation. MMIO is excluded. The source `pending_writes` field is the CPU3 alias/publication ledger, **not** the owner journal: CPU3 clears it at its instruction boundary, while the owner can reconcile at a clock/page/scalar observer. The model only bounds that source count. It does not increment or clear CPU3's pending writes. A full owner journal returns an uncommitted retry before owned RAM mutation; the same effect and bytes must be retried after reconciliation. A committed write cannot be replayed. The ROM-only page method requires the owner journal to have been acknowledged and consumes a single-use page ticket from an admitted page boundary.

`prepare` checks phase, observer reason, complete clock tape and final N/Q, due/deadline, whole ROM page and exact PIO scalar arguments before draining a copied journal. A PIC ACK reason is forbidden. `commit` validates the copied batch and all borrowed board bytes/generations before acknowledging the private shadow or updating board bytes; its fixed C++ commit loop makes no callbacks. Observer reentry is denied, and observer failure closes the model to further effects. A malformed pending-write observer therefore cannot acknowledge or mutate the board. The existing companion `Session::before_observer` is not used here.

Run the bounded controls from the repository root:

```sh
g++ -std=c++17 -O0 -pthread -Wall -Wextra -Werror \
  scripts/bochs-cpu3-native-cold-direct-ram/mock.cc -o bw-cold-direct-ram-mock
./bw-cold-direct-ram-mock
```

The mock tests copied memory and ROM aliases, cross-session/alternate/detached/shared/wrong-span board denial, MMIO and RAM-execute denial, malformed observer admission with a pending write, late-entry batch tampering and board-byte conflict, full-capacity exact retry, pending-effect close denial, distinct source/owner ledgers, reentry and fail-stop behavior. A separate control exercises the companion core's committed code-write fence; that path is outside the ROM-execute-only direct profile. These are pure C++ controls. They do **not** establish that JavaScript `Map` generations or board writes form a nonthrowing transaction.

The `BoundaryRequest` debt, deadline, kind, phase and N/Q fields are **model arguments**, not an authentication of the actual cold clock provider. Before an actual CPU3 profile can be claimed, its source adapter must bind the real provider's initialize, entry, post-PIO and query phases, including total and slice N/Q authority, and complete the retained provider's clock/reason/scalar admission before `prepare` can acknowledge anything. It must populate ABI 5 ledger fields only from validated same-DSO CPU state after clock transfer, preserve CPU3's separate alias/pending-write publication and pre-memory source capacity check, and distinguish owner pre-effect retry from committed code invalidation. It must bind one N-API environment/thread/lifetime to the process-global CPU3 singleton, retain strong references to the admitted typed arrays and ArrayBuffers, and re-resolve ordinary, non-detached, non-shared backing, offset and exact span at each synchronous commit. It must validate the real JavaScript generation provider and establish a nonthrowing commit or fail-stop on post-validation host failure. The page hook must reconcile before ROM page observation. Existing clock, PIO, page and device callbacks remain authoritative. Actual affected cold-guest parity and same-host paired measurement are later gates; neither has run for this profile.

# Predeclared form-resolved 386 admission experiment

This experiment measures whether the narrow typed grammar in [the decoded-trace plan](I80386-DECODED-TRACE-GRAMMAR-PLAN.md) forms enough contiguous Windows work to justify implementing it as an opt-in reusable executor. It is an **execution-neutral observer**. The ordinary CPU completes every step; the observer reads fetched bytes and actual successor, and does not execute, skip, or accelerate a guest instruction. The [earlier cross-mode receipt](receipts/2026-09-28-i80386-cross-mode-potential-trace.json) reported 38,839,499 optimistic ordinals in ≥8-instruction runs. Its opcode histogram cannot establish form or contiguous-run coverage for this narrower grammar.

The run must use one pinned 60,000,000-step Windows media/input configuration and two serial ordinary executions from the **same committed board revision**: baseline with all observers off, then `AT_FORM_RESOLVED_ADMISSION=1` with all execution dispatchers and other observers off. Pin and verify the BIOS, VGA ROM, HDD and event file identically in both runs. Save the two private JSON reports, then run `node scripts/summarize-i80386-form-resolved-admission.mjs observed.json baseline.json`. The reducer requires the exact 60M budget and stop reason; exact execution revision and complete reported source-hash map; each source blob matching its reported hash at that revision; identical selected guest CPU, output and board report fields; and identical media hashes, geometry, CMOS, mouse and scheduled events. It refuses a public receipt on parity failure. Publish only the reducer output: it contains report hashes and form counts, not media paths, identifiers, guest text or event payloads. The observed report embeds `formResolvedPotential` under `crossModeTraceObserver` so the established optimistic denominator remains available for audit. The runner hashes the form classifier, both reducers and the runner itself in **both** arms. Do not measure instrumented runtime as speed.

Before seeing the paired result, the stop/go threshold is **at least 15,000,000 unique admitted retired ordinals in disjoint runs of eight or more, and at least 5,000,000 of those in protected16 plus VM86**. Below either threshold, expand the grammar before building this subset as a Windows performance backend. Passing is only an upper-bound opportunity screen, not executable feasibility or a speed claim. In particular, port-I/O continuation is optimistic; no general I/O permission or device-order proof follows from a count.

Admission includes `88–8B` MOV, `39/3A/3B/3C/3D/84/85` CMP/TEST, `80/81/83 /7` CMP, short `70–7F` Jcc, `EB` jump, and byte `E4/E6/EC/EE` port I/O. It records opcode; segment, operand-size and address-size prefix signature; effective widths; ModR/M reg/mod/rm; SIB and displacement shape; register versus 16/32-bit memory EA; and read/write/control/port class. Unsupported opcodes, group extensions, lock/repeat and duplicate prefixes, incomplete forms, unexpected successor or access class, unproved RAM/port access, and cross-page RAM operands refuse. A memory candidate still uses the ordinary execution as its semantic oracle; the observer cannot prove a reusable micro-op implementation. Stack, calls/returns, far transfers, strings, shifts, remaining ALU groups, and general I/O are deliberately outside this grammar.

The denominator distinguishes completed step calls, repeat-iteration calls, no-retirement and aborted calls, and **eligible retired instruction ordinals**. Repeat iterations are excluded because one step call need not be one architectural retirement. Each eligible ordinal is admitted once or refused once; admitted runs are disjoint and capped at 64. A run ends on unsupported form, mode or CS change, physical code-page change/crossing, successor discontinuity, code/table writes, translation or other identity changes, host/DMA writes, input, IRQ/fault/chip event, deadline, REP, no-retirement or abort. Histograms report admitted forms across all runs and separately in ≥8 runs, plus refusal and end reasons per mode. This is an optimistic *observed-form* opportunity count: a reusable executor still needs exact bytes and page identity, segment/EA and permission guards, branch and flag semantics, write/fault ordering, and synchronous device-order proof before it may retire any such form itself.

The pinned 60M pair has since completed and failed the predeclared gate. See the [result and next-grammar analysis](I80386-FORM-RESOLVED-ADMISSION-RESULT.md).

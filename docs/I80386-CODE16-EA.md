# Experimental 16-bit effective-address descriptor

`decodeI80386Code16EA(bytes, {address32, segmentOverride})` parses one
caller-owned ModR/M memory operand. It accepts mod 00, 01, and 10, returns
the consumed byte count, `reg` and `rm` fields, register terms, displacement,
and segment choice, or returns `null` when the byte sequence is incomplete or
unsupported. Mod 11 and address-size override (`address32: true`) are outside
this bounded proof. It does not fetch guest bytes or inspect CPU state. The
caller must supply bytes from a currently validated code window; the pure
decoder does not itself prove that those bytes equal the guest fetch stream.

The special mod 00/rm 6 form is direct unsigned disp16 and defaults to DS.
Other BP forms default to SS; all remaining forms default to DS. Mod 01 uses
a signed disp8; mod 10 uses a signed disp16. `segmentOverride` is an explicit
segment index from ES=0 through GS=5, with `null` meaning no override. Zero
therefore selects ES. `resolveI80386Code16EA(descriptor, cpu)` reads current
BX/BP/SI/DI values and wraps the resulting offset to 16 bits. Its result
matches the existing CPU decoder's memory EA shape, including `usesEsp:false`.

`prevalidateI80386Code16EADataWindow(machine, codeWindow, descriptor, width,
access)` resolves a live EA and pairs it with the published
`prevalidateI80386Code16DataWindow` proof. It returns `null` if either
admission fails. `isI80386Code16EADataWindowValid(window)` checks the current
register-derived address and the code/data proof immediately before a future
access. A future runner must retain the instruction-byte and starting-EIP
checks, recheck the paired EA/data proof immediately before each access, and
preserve the data-window contract for page-crossing writes. This module
performs no guest access or instruction execution and makes no speed claim.

## Private ownership boundary

The factory accepts no caller board, hooks, ROM, configuration or worker options. It constructs the existing exact free ROM and actual HotDirectBoardFacade inside a separate pristine realm. The frozen public handle exposes only primitive serialized snapshots and replay/inspect/close/abort operations. Board, machine, chips, callback tables, retained buffers and worker transport remain private. Parent mutations of the generic board/machine prototypes and nested configuration do not cross that realm; generic H4 source and dynamic callback behavior remain unchanged.

Each parent message contains one complete replay resume. Every clock, memory, PAGE, PIO and PIC acknowledgement operation runs synchronously inside the same worker. There is no callback or clock IPC. Parent busy state immediately rejects concurrent resume, inspection and close requests. Snapshots are serialized copies. Worker startup/request errors, early exits and ten-second deadlines reject pending work and terminate or quarantine the worker; explicit abort abandons proof. Close requires the supplied zero-work HLT return plus the fixed completed workload's actual N/Q totals and `RPGH001` marker, then settles actual devices.

The primitive JSON protocol is bounded in bytes, depth and nodes. Complete preflight checks supported operation shapes, ordered host ordinals, independent N/Q caps, six-cycle Q clocks, debt/due/mapping chronology and physical span bounds before effects. The actual board independently checks entry/exit fields and every operation result. Device-derived horizon or semantic disagreements fail closed; this is not atomic device rollback. The bounded single-PIO-per-resume replay contract uses the authenticated post-PIO exit deadline for preflight, then verifies the actual device horizon.

Captured Worker/EventEmitter dispatch and private method shadows protect the tested receiver-leak attack. Parent infrastructure mutation is refused before factory construction. The contract excludes arbitrary modifications of Node internals, preloads, inspector, filesystem/source and process globals; it makes no generic hostile-object sandbox claim. `execArgv` and `NODE_OPTIONS` are empty for the worker.

## Future native ABI

The [source contract](../scripts/bochs-cpu3-native-owned-clock-replay/contract.md) requires a future authenticated addon and CPU to run inside this same owned worker, with local synchronous callbacks. Parent IPC would remain at resume/input/snapshot boundaries. No per-callback or clock IPC performance backend is proposed. Keep the native worker inside a bounded CLI child process: Bochs has process-wide state and native fatal guards. Native lifetime and cancellation still need qualification before integration.

Actual native batching still requires a distinct ABI, persistent ordered pending tape that survives Bochs longjmp, independent N/Q ledgers and caps, a successful-work device horizon, and flushes before memory/PAGE/PIO/ACK, fault/IRQ/HLT, inspection/snapshot/return, staging, settlement and close. Preserve original canonical trace positions, REP/fault accounting, mapping/A20, RAM generation, prefetch/TLB and device chronology. Native source/build/runtime controls, full trace/journal/state proof and a predeclared unprofiled CPU gate remain later work. No full AT, Windows/Doom, production native CLI/GUI, physical RTx or speed claim follows here.

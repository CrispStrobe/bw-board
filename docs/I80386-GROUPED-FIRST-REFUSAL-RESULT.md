# Grouped 386 first-refusal diagnostic: local bridge gate fails

The [predeclared grouped first-refusal diagnostic](I80386-GROUPED-FIRST-REFUSAL-CONTEXT.md)
completed its ordinary baseline and `AT_GROUPED_FIRST_REFUSAL_CONTEXT=1`

`b6f8f958b00113e67d28decc761e58dc21c0842c`, 60,000,000 steps in
each arm. The source-bound paired reducer reproduced the private full
candidate byte-for-byte. The [compact media-neutral receipt](receipts/2026-09-29-i80386-grouped-first-refusal-result.json)
is generated by `scripts/summarize-i80386-grouped-first-refusal-result.mjs`
and has SHA-256
`3ee45273b2bd8a8e12948a8b5b5cca120f6b00d43c23f490331a10c818acff6d`.
It verifies the exact execution revision, complete committed source-hash map,
input pins and selected reported guest state; it contains only hashes of the
private raw reports and full candidate. Those reports, host manifest and
timings are archived on the private evidence branch at commit `f9da2f8`.
The observer is execution-neutral. Its runtime is instrumentation overhead,
not a speed measurement.

counts partition every grouped refusal. The unchanged grouped admission
screen remained at **4,642,606** disjoint ordinals in runs of at least eight
overall and **4,298,838** in protected16+VM86, below its 15M/5M gate.

The predeclared **250,000 overall / 100,000 protected16+VM86 local
four-and-four bridge triage gate fails**. Protected16+VM86 reaches 96,255,
3,745 below its threshold; total is 149,213 below its threshold. These are
individual refused ordinals with admitted runs adjacent on both sides, not
new disjoint admitted-run coverage. Their potential overlaps, so neither the
opcode totals nor the bridge totals can be summed into a performance estimate.

`8E` segment moves account for **44,239** of 46,120 protected16 bridges and
**all 50,135** VM86 bridges. The strongest protected16 shape is unprefixed
16-bit `8E`, ModR/M `mod=1,/0,rm=6`, displacement 1, RAM read: 44,230
four-and-four bridges from 82,713 refusals. VM86's strongest shape is
unprefixed `8E`, `mod=3,/0,rm=2`, register source: 48,853 bridges from
113,847 refusals. These are ES loads (`/0`), but the recorder's access class
is observational and can include other reads in the completed step. The
ordinary CPU's successful execution does not prove that an optimized path
can reproduce selector validation, segment-cache state, faults, interrupt
ordering or code/data identity changes.
Outside `8E`, protected16 direct `E8` call has 1,556 local bridges; in
protected32, `FF /2` call through a 32-bit SIB memory operand has 1,048.
Both require ordered stack and control-transfer semantics, so their local
counts do not justify treating them as ready trace operations.

The next measurement should predeclare a **broader grouped grammar and
ordered-state fixture programme**, not promote `8E` alone into an executor.
First resolve the segment-state/identity cut for `8E` and the stack/control
cuts for `E8`, `C3` and `FF /2` with exact before/after state and ordered
memory/device effects in bounded fixtures. Then replay the combined candidate
over disjoint retired ordinals under all existing page, event and identity
cuts. Any later expanded observer must independently pass the unchanged
15M overall / 5M protected16+VM86 disjoint ≥8-run opportunity screen before
an executable backend or speed pair is considered. The present diagnostic
does not pass its own prioritization gate and supports no executor or speed
claim.

# Windows 3.0 bounded guest milestone

The experimental 386 AT profile boots the pinned PC DOS 3.2 / Windows 3.0 EGA
image to the 640×350 Program Manager desktop. A second immutable run sends a
real Set-1 Enter make/break pair through the modeled 8042; the selected File
Manager icon opens and displays the `C:\WINDOWS` tree and free-space value.
The compact [receipt](receipts/2026-09-20-windows300-desktop.json) binds both
execution revisions, the recorded local dependency hashes, all external input
hashes, raw reports, decoded RGB results, and the exact keyboard timeline.
External media and rendered guest pixels remain outside the repository.

The runner intentionally retains `diagnosticOnly: true` and
`windowsBootAccepted: false`. CPU mode, nonzero VGA planes, or an exhausted
instruction budget cannot self-certify a desktop. The receipt is the separate
audited milestone: raw four-plane VGA snapshots were decoded to 640×350 RGB,
the Program Manager and File Manager contents were visually checked, and both
runs had no host refusal, CPU halt, or shutdown.

The last disk blocker was a bounded scheduling issue. With the former
256-functional-cycle ATA inter-sector BSY interval, Windows entered a chained
timer handler during an eight-sector BIOS read. The interval expired inside
that handler, so the resumed IBM BIOS saw status `58h` after sector four and
mistook the next DRQ for command completion; INT 13h eventually returned
`AH=80h`, carry set. The 8192-cycle profile covers the longest chained IRQ0
service observed in this exact guest trace and preserves autonomous device
progression. It is a functional guard for this configuration, not measured
rotational timing or a guarantee for arbitrary handlers.

This demonstrates the pinned Windows 3.0 standard-mode installation and one
keyboard-driven application launch. It does not establish compatibility with
other Windows releases, enhanced mode, arbitrary applications or hardware.

## Reproduce the desktop/application run

Use Node22 and the external inputs whose hashes are listed in the receipt.
Run from a clean, fixed checkout; the runner checks the execution revision and
dependency hashes before and after execution. The original HDD is cloned in
memory, so this diagnostic does not overwrite the input file.

```sh
AT_BIOS_ROM=/path/to/ATBIOS-REV1.rom \
VGA_BIOS_ROM=/path/to/vgabios.bin \
AT_HDD_IMAGE=/path/to/PCDOS320-WIN300-EGA.img \
AT_POST_STEPS=120000000 \
AT_WINDOWS_ENTER_STEP=100000000 \
AT_PROGRESS_OUTPUT=/tmp/windows-progress.json \
node scripts/run-i80386-windows300.mjs > /tmp/windows-action.json
node scripts/render-i80386-windows-vga.mjs /tmp/windows-action.json /tmp/windows-final.ppm
```

The final image should show File Manager. `keyboardAction.beforeVga` and
`keyboardAction.afterVga` preserve the desktop and ten-million-instruction
response snapshots; render either by placing it under a temporary JSON `vga`
field. Check the actual accepted make/break events and visual contents, rather
than treating a budget stop or the runner's diagnostic flag as acceptance.
The strict renderer only admits the recorded 640×350 planar register layout.

## Notepad save and fresh-boot reopen

The [editor persistence receipt](receipts/2026-09-20-windows300-editor-persistence.json)
records keyboard-only creation of `C:\OWNED.TXT` containing the 17 ASCII bytes
`astra windows 300`. The original input contains no such file. Independent
inspection finds the new root entry and matching FAT copies in the output
clone; a fresh reset/remount opens that file in Notepad and shows the text.
The file hash is `1f6737e67b3319c3257ded96c40f99f7ef137a840067c9fbe7e2bab4df56fcee`.

Use `AT_WINDOWS_KEY_SCRIPT=test/fixtures/windows300-editor-save.json` and
`AT_HDD_OUTPUT=/path/to/new-output.img` with the original inputs and 120M budget.
For the 115M reader, select `windows300-editor-remount.json`, use that output as
`AT_HDD_IMAGE`, set `AT_HDD_EXPECTED_SHA256` to the writer's output hash, and set
`AT_HDD_PARENT_REPORT` to its JSON report. Do not also set `AT_WINDOWS_ENTER_STEP`.
Output paths must be new; the current harness verifies parent/image linkage.
The historical reader preceded that automatic linkage check, so its actual
input/output hashes were also compared independently in the receipt audit.

The successful sequence uses Alt+F then A for Save As. The earlier Ctrl+S
attempt appended the filename to the document and did not save a file; it is
preserved as an excluded interaction diagnostic.

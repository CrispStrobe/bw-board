# Windows 3.0 bounded guest milestone

The experimental 386 AT profile boots the pinned PC DOS 3.2 / Windows 3.0 EGA
image to the 640×350 Program Manager desktop. A second immutable run sends a
real Set-1 Enter make/break pair through the modeled 8042; the selected File
Manager icon opens and displays the `C:\WINDOWS` tree and free-space value.
The compact [receipt](receipts/2026-09-20-windows300-desktop.json) binds both
execution revisions, every executed local source file, all external input
hashes, raw reports, decoded RGB results, and the exact keyboard timeline.
External media and rendered guest pixels remain outside the repository.

The runner intentionally retains `diagnosticOnly: true` and
`windowsBootAccepted: false`. CPU mode, nonzero VGA planes, or an exhausted
instruction budget cannot self-certify a desktop. The receipt is the separate
audited milestone: raw four-plane VGA snapshots were decoded to 640×350 RGB,
the Program Manager and File Manager contents were visually checked, and both
runs had no host refusal, CPU halt, or shutdown.

The last disk blocker was a bounded scheduling issue. With the former
256-functional-cycle ATA inter-sector BSY interval, Windows entered a chained
timer handler during an eight-sector BIOS read. The interval expired inside
that handler, so the resumed IBM BIOS saw status `58h` after sector four and
mistook the next DRQ for command completion; INT 13h eventually returned
`AH=80h`, carry set. The 8192-cycle profile covers the longest chained IRQ0
service observed in this exact guest trace and preserves autonomous device
progression. It is a functional guard for this configuration, not measured
rotational timing or a guarantee for arbitrary handlers.

This demonstrates the pinned Windows 3.0 standard-mode installation and one
keyboard-driven application launch. It does not establish compatibility with
other Windows releases, enhanced mode, arbitrary applications or hardware.

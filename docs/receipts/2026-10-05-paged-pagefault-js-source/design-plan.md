# Page-fault recovery and retry: source design

This is an external design for a new finite owned profile. No new JS instruction, native preparation, build, addon load or guest execution has occurred. The qualified INT/IRET profile and its 41 N/Q result remain unchanged; its results are published in [PR 384](https://github.com/CrispStrobe/bw-board/pull/384). The detailed addresses, encoding, source hashes, guards and proposed controls are in `plan.json`.

The program runs at CPL 0 with 16-bit code and 4 KiB paging. Linear code 7000 maps to physical A000; initially nonpresent linear data 8000 will map to B000; linear stack D000 maps to C000 with initial ESP E000. GDT 0000, page directory 1000, table 2000 and IDT 3000 are accessible through owned identity mappings. Physical aliases 7000, 8000 and D000 contain poison and must remain unchanged. These ten full physical pages are retained and compared at declared comparable cuts.

A present type-6 gate for vector 14 at IDT 3070 targets CS 18:7020; IDTR limit is 0077. At 7000, `MOV AX,1234` preserves the EAX upper half inherited from the PG setup. At 7003, `MOV [8000],AX` must produce exactly one nonpresent supervisor-write page fault: vector 14, error 2, CR2 8000 and restart IP 7003. The failed attempt must not commit an operand write to physical B000.

The real native frame is FLAGS 0002 at CFFE, CS 0018 at CFFC, restart IP 7003 at CFFA and error 0002 at CFF8. Its eight bytes are `02 00 03 70 18 00 02 00`. JS creates its own genuine translated fault frame; each backend's actual store/read chronology is retained independently. Neither synthetic frames nor forced callback-order equality are permitted.

The handler executes `MOV dword [2020],B003`, `MOV EDX,CR3`, `MOV CR3,EDX`, `ADD SP,2`, then `IRET`. Reloading CR3 with 1000 is legal for the strict 386 profile and authentic Bochs source flushes the TLB even when its value is unchanged. INVLPG is unavailable before Intel486, as documented in the [Intel instruction reference, IA-32 Architecture Compatibility](https://cdrdv2-public.intel.com/874240/325462-090-sdm-vol-1-2abcd-3abcd-4.pdf). No INVLPG, PSE or CR4 extension enters this fixture.

`ADD SP,2` discards the actual error word. IRET restores ESP E000 and CS 18:7003. The faulting store retries exactly once, now committing 1234 at B000; the next instruction reads that word into CX. Stop at 18:700A before HLT. Final expected EAX is 80001234, ECX 1234, EDX 1000, flags 2, CR2 8000 and CR3 1000. The original B000 upper bytes and all poison aliases remain intact.

The existing FAULT hook is sufficient at the ABI level, but the old INT runner is insufficient. Prepared `cpu.cc:60–70` returns immediately after exception delivery, before the first handler instruction. `runtime.inc:423–433` requires N to advance by one while Q remains unchanged; the returned reason is FAULT (2). The genuine JS faulting step restores the instruction state, delivers its frame and returns zero, without an ordinary six-clock board charge. A new driver must recognize exactly this owner/vector/error/CR2/fault-count transition and invoke exactly one real JS fault attempt. Other zero-Q prefetch returns remain unmatched phase records. Attempt ordinal, successful Q, charged N, fault serial and committed writes must be separate; handler entry can share completed Q with the pre-fault boundary.

Native DS cache validity is expected to change from loaded 1 to 7 on the first store, even though paging faults afterward. The prepared source chain is `cpu.h:5341–5360` → `access.h:190–193` → `access.cc:82–102` → `access2.cc:53–77`: segment write checks set ROK/WOK before translation. This is a source-backed expectation requiring the first native capture to confirm it, not an observed PF result. SS is expected to become 7 at the first real frame write. Descriptor index and valid are separate fields; no masks or broad cache allowances are proposed. Native inhibit and actual JS MOVSS/MOVSP shadow phases remain separately retained.

PDE/PTE A/D effects are checked as full bytes. Expected final leaves include code A023, IDT 3023, stack C063, table 2063 and repaired data B063, with the directory 2023. Code fetch must not dirty its leaf. Native combined A/D updates and JS split updates may differ in count and timing; this design claims no observed new native chronology or generation count. CR3 reload is exercised, but recovery from a nonpresent page alone does not establish stale-positive-translation invalidation.

The first proposed source slice is only a fixed profile, private genuine JS reference, SOURCE note and test file. Source controls would prove encoding, boot ownership, gate/frame/error/refusal policy, page effects and attempt/Q distinction. A separately reviewed bounded actual JS control would then retain all attempts, genuine delivery, full CPU/board/ten pages and tapes. Expected runtime counts come from that capture rather than guessed Q values. Native policy, distinct build authority, fault-aware driver and default-disabled hosting follow as separately reviewed slices. A fresh DSO is mandatory; the old qualified DSO is inadmissible.

All native raw 166 words and full resume metadata remain retained. Every JS-represented field, full board and all ten pages are compared only at explicitly comparable cuts. PG entry, prefetch and generic zero-Q phases stay explicitly unmatched with intact records; they must not indirectly assert page equality through board RAM hashes. The first actual mismatch is retained for source review. Evidence uses the qualified bounded lossless gzip/outcome protocol with unchanged 16 MiB stored-file cap and 64 MiB decoded cap. This finite correctness fixture makes no full-OS, speed, physical-386 calibration or adoption claim.

Provenance: `prepared-source-provenance.json` authenticates nine small selected prepared Bochs files streamed from the sole existing INT static-build ZIP. `plan.json` also binds the held JS, runtime, clock and ABI files to compiled revision 4a4ec3c9. The retained filename-selection correction was a read-only lookup issue, not a guest or control failure.

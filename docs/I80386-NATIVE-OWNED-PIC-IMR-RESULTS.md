# Fixed PIC IMR native results (2026-10-02)

The bounded free PIC IMR fixture now passes actual native capture-OFF and capture-ON runs. It reads masked master/slave IMR ports `0x21` and `0xa1`, obtaining `[255, 255]`, while retaining the existing PIT witness `[50, 18]`, two expected page faults and one IRQ. This qualifies the fixed experimental fixture; it does not switch the default runner, qualify a general AT guest, or establish a speed improvement.

The native guest completed 448 resumes with 100,702 native ticks and 100,700 successful quanta. Capture-OFF matched the actual JavaScript reference at all six named cuts and terminal board state. Root parity passed 1,408 checks; independent OFF audit passed 1,205 checks. Capture-ON retained every stored 166-word native architecture snapshot, descriptor array, logical/physical counter, complete board checkpoint and raw RAM hash exactly against OFF. Its full trace contained 1,649,374 canonical rows, 209,888 host-journal rows and 201,402 ordered N/Q events. Independent ON audit passed 1,134,435 checks, including all 35 PIO events and four IN values.

The exact IN chronology is PIT `0x40 → 50` at JavaScript attempt 18, PIT `0x40 → 18` at attempt 20, PIC `0x21 → 255` at attempt 96, and PIC `0xa1 → 255` at attempt 98. Native PIO records occur before the instruction's post-completion tick, so their completed native N count is the current JavaScript attempt minus one. The source-bound STEP reconstruction orders successful Q before N and failed steps as N only; it does not relabel the JavaScript journal as an observed native callback order. Native canonical N/Q tuples and Q kinds match the actual host journal exactly.

The JavaScript reference exports ten CPU fields. Eight match exactly; EDX and CR0 follow the already documented per-core profile: native EDX is zero versus JavaScript `0x300`, and CPU-level-3 Bochs forces CR0 bits with `JS_CR0 | 0x7ffffff0`. Each core's exact eight reset-witness bytes are checked against its own recorded reset before zeroing only RAM `0x510..0x517` for canonical comparison. Native raw RAM SHA is `19e8a7ebcd8260e1a33d7ebc5d11027e04d037b735e2f50f0ab53a4092d827ee`; JavaScript raw SHA remains `887b7eb9959044f45868a71c29c5c013d65ec0ad3e0205c738719757e63b0ffb`. Both use canonical SHA `e5f3f9f0ee95f1828b6dd6b28149d7d1e1dbaa77cb79268918b5c7b469601cfd`. No other RAM range or CPU state is normalized, and the unrecorded JavaScript architecture words are not invented.

The actual JavaScript runner independently recorded full PIC state immediately around each read after clock catch-up, confirming no read/ACK state change with polling unarmed. The native capture exports returned PIO values, ordered chronology and endpoint/checkpoint state, not PIC snapshots immediately before and after each read. That distinction remains explicit. Poll-armed reads are refused before PIC read/ACK effects; earlier pre-PIO clock flushes may already have taken effect, with no rollback claim.

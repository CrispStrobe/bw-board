# Stock xv6 usertests: next bounded marker

The [stock xv6 prefix receipt](receipts/2026-09-27-xv6-stock-usertests-prefix.json) stopped intentionally at `createdelete ok\n` after 163,992,924 guest steps. The [next-marker receipt](receipts/2026-09-28-xv6-stock-usertests-linkunlink.json) records a fresh pinned-media run that passed the `linkunlink ok\n` marker after 232,651,147 steps, within its declared 300,000,000-step budget. The raw report and host record are preserved in the private firmware evidence repository at commit `998d577`. This is a bounded prefix result, not a full-suite result. In pinned MIT xv6-public revision `eeb7b415dbcb12cc362d0783e41c3d1f44066b17`, `main()` calls `linkunlink()` immediately after `createdelete()`; its next completion marker is `linkunlink ok\n`. The program then proceeds to `concreate()` and many further tests.

[`scripts/probe-xv6-usertests-next-marker.py`](../scripts/probe-xv6-usertests-next-marker.py) pins the existing licensed local Bochs BIOS, VGA BIOS, stock xv6 boot disk, filesystem disk and kernel by SHA-256. It checks a clean board revision, the xv6 source revision and test order, then records hashes of the ordinary stock probe and core board sources. Set `XV6_SOURCE_DIR`, `XV6_IMAGE_DIR` and `XV6_OUTPUT_DIR` to local paths as needed; their defaults are `/tmp/xv6-public`, `/tmp/xv6-stock-4m` and `/tmp/xv6-usertests-next-marker`. `--preflight` performs only quick checks. Once the shared guest slot is free, `--run` starts a **fresh** 4 MiB stock xv6 boot with `usertests\r`, ordinary CPU execution and a 300,000,000-step ceiling. It stops on `linkunlink ok\n`, or reports that the budget expired first. Rebooting from the original pinned filesystem image is intentional: xv6 creates `usertests.ran`, and a second command in the same filesystem state would decline to run.

Raw serial, local media paths and diagnostic stderr go only to the configured `XV6_OUTPUT_DIR`. If the old prefix recurs and the next marker is reached or the declared budget expires, the wrapper writes a source/media-bound candidate receipt there. The candidate carries hashes and marker booleans, not the guest transcript or local paths. A missing old prefix, unexpected probe exit or media mismatch fails closed. Reaching `linkunlink ok` establishes only that next test. It does **not** establish complete `usertests` or filesystem integrity beyond that test.

This probe does not supply a QEMU/Bochs oracle transcript. An oracle comparison should use a separate copied writable disk and the same image/source hashes; it is not implied by the board marker probe. No QEMU/Bochs oracle run was started during preparation. The subsequent board continuation reached `linkunlink ok\n`; it provides no independent oracle comparison.

## Next source-order marker: `concreate ok\n`

At the same pinned xv6 revision, `main()` invokes `concreate()` after `linkunlink()`, and `concreate()` prints `concreate ok\n` on completion. [`scripts/probe-xv6-usertests-concreate.py`](../scripts/probe-xv6-usertests-concreate.py) pins the same source revision, ordinary board sources, firmware and stock disk images. Its `--run` boots from the original filesystem image, sends `usertests\r`, requires the prior `linkunlink ok\n` marker, and stops at `concreate ok\n` or a predeclared 600,000,000-step ceiling. The [concreate receipt](receipts/2026-09-28-xv6-stock-usertests-concreate.json) records a fresh run reaching the marker after 594,997,630 steps, 5,002,370 steps under the ceiling. The raw report and host record are preserved privately at firmware commit `ec147a2`. This is still a bounded prefix result; the later tests and final suite marker were not observed.

## Next probe: final suite marker

Another single-test replay would pay the now measured 594,997,630-step boot and prefix cost again before testing any later behavior. The pinned `usertests.c` invokes many more tests and ends with `exectest()`, which executes `echo` with arguments `ALL TESTS PASSED`; the shell then returns to `$ `. The more informative next board probe is [`scripts/probe-xv6-usertests-full-suite.py`](../scripts/probe-xv6-usertests-full-suite.py), which requires the prior `concreate ok\n` marker, records ordered `createdelete`, `linkunlink` and `concreate` serial positions, and stops only on `ALL TESTS PASSED\n$ `. It also checks the pinned `echo.c` formatting. This final marker is the stock suite's completion signal, rather than proof from an independent filesystem oracle.

The proposed run has a **predeclared 3,000,000,000-step ceiling** and writes private stderr progress every 50,000,000 steps. Its `--preflight` checks source/media pins without starting a guest; `--run` starts from the original pinned filesystem image, with `XV6_SOURCE_DIR`, `XV6_IMAGE_DIR` and `XV6_OUTPUT_DIR` available to select local paths. At the concreate run’s observed average of about 810,000 guest steps per wall second, the full ceiling would take roughly 62 minutes of exclusive CPU time; later tests may run at a different rate. The budget is an upper bound, not a prediction of completion: the run may stop at the budget first. If it does, the raw private transcript and last progress entry identify the actual reached test without claiming a full suite pass. No full-suite board run was started during this preparation.

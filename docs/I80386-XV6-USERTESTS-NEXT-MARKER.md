# Stock xv6 usertests: next bounded marker

The [stock xv6 prefix receipt](receipts/2026-09-27-xv6-stock-usertests-prefix.json) stopped intentionally when `createdelete ok\n` appeared at 163,992,924 completed guest steps. It did not run the remaining tests and is not a full-suite failure. In pinned MIT xv6-public revision `eeb7b415dbcb12cc362d0783e41c3d1f44066b17`, `main()` calls `linkunlink()` immediately after `createdelete()`; its next completion marker is `linkunlink ok\n`. The program then proceeds to `concreate()` and many further tests.

[`scripts/probe-xv6-usertests-next-marker.py`](../scripts/probe-xv6-usertests-next-marker.py) pins the existing licensed local Bochs BIOS, VGA BIOS, stock xv6 boot disk, filesystem disk and kernel by SHA-256. It checks a clean board revision, the xv6 source revision and test order, then records hashes of the ordinary stock probe and core board sources. Set `XV6_SOURCE_DIR`, `XV6_IMAGE_DIR` and `XV6_OUTPUT_DIR` to local paths as needed; their defaults are `/tmp/xv6-public`, `/tmp/xv6-stock-4m` and `/tmp/xv6-usertests-next-marker`. `--preflight` performs only quick checks. Once the shared guest slot is free, `--run` starts a **fresh** 4 MiB stock xv6 boot with `usertests\r`, ordinary CPU execution and a 300,000,000-step ceiling. It stops on `linkunlink ok\n`, or reports that the budget expired first. Rebooting from the original pinned filesystem image is intentional: xv6 creates `usertests.ran`, and a second command in the same filesystem state would decline to run.

Raw serial, local media paths and diagnostic stderr go only to the configured `XV6_OUTPUT_DIR`. If the old prefix recurs and the next marker is reached or the declared budget expires, the wrapper writes a source/media-bound candidate receipt there. The candidate carries hashes and marker booleans, not the guest transcript or local paths. A missing old prefix, unexpected probe exit or media mismatch fails closed. Reaching `linkunlink ok` establishes only that next test. It does **not** establish complete `usertests` or filesystem integrity beyond that test.

This probe does not supply a QEMU/Bochs oracle transcript. An oracle comparison should use a separate copied writable disk and the same image/source hashes; it is not implied by the board marker probe. No QEMU/Bochs run or heavy board run was started during preparation.

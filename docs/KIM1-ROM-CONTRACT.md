# KIM-1 replacement ROM contract

Independently implement with your own code, memory layout, and control flow. Only hardware facts and black-box requirements follow. The output is exactly 2,048 bytes, two 1 KiB banks in address order, $1800–$1BFF then $1C00–$1FFF. NMOS documented 6502 opcodes only. The physical CPU is clocked at 1 MHz. The linker should fill unused bytes and place the vector words at $1FFA/$1FFC/$1FFE, mapped to $FFFA/$FFFC/$FFFE. Workspace is $00EF–$00FF and $17C0–$17FF. Avoid zero page $00–$EE and system/user RAM otherwise. Prefer internal storage at the low end of the keyboard RIOT RAM. Do not overwrite user program bytes on reset. External end address for Q is $17F7/$17F8. Soft interrupt vectors are $17FA/$17FB NMI and $17FE/$17FF IRQ/BRK. Set sensible defaults when empty and honor user edits. Stack frame and decimal flag should be handled normally.

Documented monitor ABI for compatibility with lessons and software. Implement the fixed addresses using trampolines as useful. $1C00 is the NMI/STOP register-save entry. $1C4F returns to monitor command handling. $1E5A GETCH reads seven-bit TTY ASCII to A and preserves X. $1EA0 OUTCH sends A over TTY and preserves A/X/Y. $1E88 initializes monitor I/O. $1F19 SCAND displays the selected address in zp $FA/$FB and its memory byte. $1F1F SCANDS displays $FB, $FA and $F9 as three hexadecimal bytes. $1EFE AK returns zero if no key, nonzero if present. $1F6A GETKEY returns native key numbers zero through 20 and 21 if none. Key numbers are the positions in the matrix below, left to right and then by row. $1E4C outputs the low nibble of A as ASCII hex and $1F63 increments the address pointer. These are compatibility targets, not constraints on private code. $1F4E may be left unallocated unless required by a verified public handshake.

Keypad RIOT: PA $1740, DDRA $1741, PB $1742, DDRB $1743. PB1–PB4 select decoded lines. Lines 0..2 scan rows; seven columns go to PA6..PA0 in that order, active low. Rows are 0 1 2 3 4 5 6, then 7 8 9 A B C D, then E F AD DA + GO PC. ST is hardware NMI, RS hardware reset, SST generates NMI after one user instruction in the emulator. Decimal digits and commands must trigger once per press, and continue scanning and refreshing while waiting for release. Emulator keys can be held 50ms and released for 35ms. Outputs 4..9 select the six LED digits left to right. PA0..6 drive segments a..g active high when set as output. For reading the keypad set DDRA to input. For output use DDRA $7F. Start at display 0000 and the byte at 0000, commonly 000000. AD and DA switch destination for rolling hexadecimal entry. + advances without changing mode. PC restores the saved execution address. GO restores user registers then executes the selected address. ST, SST and BRK update saved PC and A/X/Y/P/SP. Saved PC low/high at $EF/$F0, status $F1, SP $F2, A $F3, Y $F4, X $F5. A test program at $0200 with LDA #$42, STA $0300, JMP to its own tail displays 0200A9 before run, 02028D after one SST, and 02054C after GO then ST.

TTY: with display/rows deselected (decoded >9), PA0 low selects TTY mode and PA0 high selects normal keypad mode. Set PB5 low to pass incoming serial to PA7, and PB0 high when idle. Incoming start and data are on PA7, outgoing bits on PB0. 300 baud, about 3333 CPU cycles per bit, low start, eight data bits LSB first (top bit may be parity, mask to 7-bit), at least one high stop. Board TTY already provides hardware echo. On reset the simulated terminal queues RUBOUT $7F when it observes PA reads with PB5 low. Consume it then emit a prompt containing KIM. Fixed 300 baud is fine, or use an independent baud measurement if you have room. Keep user zero page available for cc65. TTY commands accept hex in either case. Digits then space select an address and print address/data (e.g. 0200 A9), digits then period write the low byte and advance, G runs selected address, CR or + advances, LF or - goes back, DEL aborts current input and displays a prompt. Tolerance for historical TTY command aliases is welcome. The regression uses 0200 5A. to write and 0200 G to run. Original user programs call OUTCH/GETCH. Relay bytes including CR, LF, ESC faithfully.

Paper tape via TTY L and Q, separate from audio cassette. MOS records start ';', then two hex digits for byte count, four for start address (high byte first), data octets as ASCII pairs, and a 16-bit unsigned sum of count, address bytes and data, as four hex digits high first. A zero-count record uses the address field for number of preceding data records, and is checked the same way. CR/LF, NUL, and XOFF delimit/pad. Typical data record is 24 bytes. Load ignores leaders, validates the checksum and record totals, and reports errors visibly. For sample input L;030200A9420000F0 followed by newline then ;0000010001, must store A9 42 00 at $0200 and complete. A bad sum must produce a visible error. Q dumps from the selected address using the end address at $17F7/$17F8. Use an independently designed record writer. Finish with an EOF record and XOFF. Audio cassette $1800 / $1873 is lower priority because the current machine has no cassette signal path. Report this explicitly if it cannot be qualified.

Use only this contract. Request further black-box facts through the coordinator.

## Provenance and verification

The author received this contract. The verifier used the historical ROMs and
program files as test inputs. The deliverable contains independent monitor
assembly and its reproducibly built images.

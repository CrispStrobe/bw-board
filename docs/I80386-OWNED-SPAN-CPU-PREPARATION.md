# Private span paired CPU gate: preparation

The proposed single hosted gate compares unchanged `fe1`/103 compiled inputs with private span runtime `bbf2a73e3d9090e73fe7037f4b8dbd4f6248aaa1`/116 inputs, reusing the original CI addon. It runs two discarded warmup pairs and seven alternating measured pairs in fresh sequential bounded children. Adoption requires at least 10% less mean whole-process execution CPU and all seven favorable pairs, with complete fixed-fixture semantics in every child. There is no performance result yet.

Its three native semantic prerequisites already passed in run `37056398077` at pinned preparation `80d228ee5452f380655a16c4bc823beb76e781c1`, with separate original official artifact and later root/peer aggregate audits. The CPU job authenticates that genuine artifact, streaming historical trace/journal hashes while selectively extracting small captures, inputs and parity records. It does not execute the three cells again. Later aggregate audits are source-packet copies, not invented files inside the old ZIP.

A separately pinned checkout reuses the reviewed source-only materializer and exact raw-Git reconstruction. Two declared inverse seams bind its event-head check to the fixed tooling head while recording the actual CPU event head separately from `toolingHead`; the current CPU publication head and files are independently authenticated against Git. The unchanged scheduler still creates all 445 full native snapshots and six board checkpoints. The original process.cpuUsage window includes callbacks, snapshots and GC, and excludes creation, settlement and final serialization. Existing eight-byte own-reset RAM/profile policy and ordinary array snapshots remain unchanged.

All new actual children, captures, inputs, exits, streams, source/provenance guards and hardware context will be retained, including incomplete or negative results. Historical binary artifacts and large three-cell streams remain explicitly hash-bound external inputs rather than being duplicated in the new upload. Source-only preparation and review are required before a single PR-triggered gate is authorized. This is a new span candidate, not a retry of rejected dispatch/bulk experiments, and establishes no full AT/Windows, physical-clock RTx or 10× claim.
